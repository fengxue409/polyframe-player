# P34 皮肤切换（亮 / 暗双主题）

零功能改动，只动视觉层：全站配色从「一套写死的暗色」变成「两套可切换的 token」。

## 1. 为什么这次能低成本做到

P28 已经把颜色收敛成 App.vue 里的 CSS 变量，所以切皮肤不需要给任何组件传参、不需要重建视图，
只需要把 `data-theme` 写到 `<html>` 上，让一层覆盖生效。切换是**纯 CSS** 的，零重渲染。

代价是必须先清掉散落在组件里的硬编码色值 —— 这些是亮色下"局部还是深色"的唯一来源。
本批把它们全部换成了 token（见 §4 清单）。

## 2. 结构

```
:root { ... }                      暗色 = 默认，所有结构性 token（圆角/间距/字号/动效/层级）
:root[data-theme='light'] { ... }  只覆盖颜色，结构与暗色完全共用
:root[data-theme='light'] .force-dark { ... }  把颜色 token 就地还原成暗色一套
```

因为圆角/间距/字号/动效两套共用，两套皮肤的结构永远一致，不会出现「改了一边忘了另一边」。

### 2.1 三处必须同步（漏一处就有可见缺陷）

| 位置 | 作用 | 漏掉的后果 |
|---|---|---|
| `index.html` 内联脚本 | 首帧之前写 `data-theme` | 先渲染一帧暗色再跳亮，闪白/闪黑 |
| `stores/theme.ts` `apply()` | 切换时写属性 + 落 localStorage | 点了没反应 / 重启回到默认 |
| 主进程 `pf:appearance-set` | `mainWindow.setBackgroundColor()` | 亮色下拖窗口边缘露出深色条 |

主进程那条只影响「新露出区域的填充色」，色值只接受 `#rrggbb`（其余忽略），不参与渲染逻辑。

### 2.2 恒暗区

视频舞台在亮色下依然是黑的，但里面的文字若继续吃 `--text-faint` 就会变成**深灰压黑底**——
实测播放页的占位文字（「输入 HLS / MP4 直链后点击播放」）与卡顿提示都读不清。

处理方式是给舞台容器加 `.force-dark`，在该作用域内把整套颜色 token 还原成暗色值，
子元素无需逐个适配。已挂两处：`PlayerView` 的 `.video-wrap`、`ParseView` 的 `.screen`。

> 以后新增颜色 token，记得同步 `.force-dark` 块，否则视频区内会用到亮色值。

## 3. 亮色 token 的关键取舍

| 项 | 暗色 | 亮色 | 原因 |
|---|---|---|---|
| `--accent` | `#4c7dff` | `#2b58d4` | 同一支蓝在近白底上对比只有 3.1，白字压上去不可读；主按钮必须整体加深 |
| `--accent-hi` | 更亮 | 更深 | 亮色下 hover「加深」才符合直觉 |
| `--text` | `#e2e7f0` | `#17202e` | 白底上 14.9:1 |
| `--text-dim` | `#9aa5b8` | `#4d5972` | 6.6:1 |
| `--text-faint` | `#7b879b` | `#6c7893` | 4.7:1，仍过 AA |
| `--shadow-1/2/3` | 深、近黑 | 淡、扩散大 | 白卡片配深阴影会像贴了黑边 |
| `--card-highlight` | 顶部 1px 白高光 | `none` | 白卡片上加白高光毫无意义 |
| `--fallback-a/b`、`--fb-l*` | 深 | 浅 | 无海报占位块要跟着反色，否则亮色页里一排黑框 |

`--ok / --warn / --danger / --info` 亮色版统一压深（`#0b7f4f` / `#8f5c00` / `#c62839` / `#14608f`），
它们的 `-bg / -line` 是 `color-mix(var(--x) …)` 派生的，会自动跟随，不必各写一份。

`::selection` 也从「42% 蓝 + 白字」改成「34% 蓝 + `--text`」：浅蓝底压白字只有 1.8:1。

## 4. 本批新增的材质 token（原先都是硬编码）

`--panel-hover` `--line-hover` `--btn-hover` `--btn-active` `--input-focus-bg` `--track`
`--row-hover` `--card-highlight` `--scroll-thumb` `--scroll-thumb-hi` `--skeleton`
`--skeleton-glow` `--toast-bg` `--modal-bg` `--mask` `--topbar-bg` `--shadow-color`
`--fallback-a/b` `--fb-s` `--fb-s-2` `--fb-l1` `--fb-l2` `--fb-ink`

替换掉的硬编码（跨 9 个文件）：`#151b27` `#212a3b` `#1a2130` `#36415a` `#333e55` `#33405a`
`#0f141d` `#161d29` `#131926` `#1b2432` `#131a2a` `#1a1626` `#ff9d66` `#d7c08a` `#ffb4bd`
`#242c3b` `#354057` `#0e121a` `rgb(24 30 41/.96)` `rgb(4 6 10/.66)` `rgb(8 11 18/.68)`
`rgb(255 255 255/.045)`（侧栏 hover）等。

**刻意保留的硬编码**：图片/封面上的叠加层（`rgb(6 9 14 / …)`、`rgb(255 255 255 / …)`）——
它们压在海报上，与页面底色无关；以及视频区内部的 `#000` 与弹幕颜色。

## 5. 入口

- 顶栏右上角图标按钮：显示**当前**皮肤（月亮=暗 / 太阳=亮），点击切到另一套
- 设置页 → 外观 → 分段控件（与顶栏按钮同源，任一处改动另一处立即同步）
- 默认暗色；选择落 `localStorage['pf.theme']`

侧栏「设置」图标同时从齿轮换成滑块 —— 17px 的齿轮在图标轨里会跟主题太阳图标撞脸。

截图脚本：

```bash
node ui-snapshot.mjs 1440x900                 # 暗色（默认）
PF_THEME=light node ui-snapshot.mjs 1440x900  # 亮色，落在 .screenshots/ui/1440x900-light/
```

亮色模式靠 `localStorage` 驱动，脚本是先写入键值再 reload —— 直接改 `data-theme` 属性没用，
那样设置页的分段控件会和画面对不上。

## 7. 已知边界

- **mpv 原生子窗口**、弹幕（Canvas / ASS）、封面图不跟随皮肤：它们与页面底色无关。
- 窗口**启动瞬间**的底色仍是暗色（主进程读不到 renderer 的 localStorage）。
  `show: false` + `ready-to-show` 让这层几乎不可见；切换之后的拖拽/缩放已由 IPC 同步。
- 视频舞台在亮色下是「白卡片里嵌一块黑」，边界比暗色更硬。这是刻意的：
  亮底上视频会失去边界感，且 mpv 原生窗口的边缘更难对齐。
