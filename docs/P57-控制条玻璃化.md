# P57 全屏控制条：半透明玻璃化 + 可读性保底

> 需求：底部进度条栏改为半透明样式，给出合适的背景透明度与模糊效果，保证进度条上的
> 文字、图标、进度指示在**各类背景内容**下仍清晰可读，并与整体界面风格一致。

## 1. 先决条件：画面必须铺满，否则模糊是空转

改样式之前先改了一条几何 —— 这不是顺手优化，是玻璃成立的前提。

P54 的布局是「画面高度 = 100% − 72px，控制条坐在下方那条纯黑带上」。那时这么做是对的：
原生控制条还在，画面缩一条，原生条就不会被自研按钮压住。但 P55 把全屏下的原生控制条
**整体下线**（`:controls="!isFullscreen"`）之后，这条 72px 就成了纯浪费：画面白白少一截，
而条子背后是 `#000`。

于是 `backdrop-filter` 采样到的只有一个纯黑矩形 —— **模糊了等于没模糊**，半透明也看不出
半透明。所以：

```css
/* 改前 */
.video-wrap:fullscreen video { height: calc(100% - var(--pf-fs-bar)); }
/* 改后 */
.video-wrap:fullscreen video { height: 100%; }
```

画面满幅，控制条压在下沿之上（探针 `overlapPx: 72`、`videoBottomGap: 0`）。

**不受影响的两处**（都按 wrap 矩形算，不按 video 元素算）：

- **mpv 内核**：子窗口矩形 = wrap 矩形 − `FS_BAR_H`（`syncMpvRect`），仍停在条子上沿。
  Win32 子窗口恒画在 DOM 之上，这条让位是硬约束，改不得。
- **弹幕层 / 快进提示**：`bottom: var(--pf-fs-bar)`，仍让开这一条 —— 玻璃后面的弹幕
  既看不清也读不完，等于白排。

顺手清掉的三条 P54/P56 遗留（都是为了「画面让出 72px + 收起时长高」存在的）：

| 删掉的东西 | 原因 |
|---|---|
| `.fs-idle video { height: 100% }` | 画面已经是 100%，收起不再需要改高度 |
| `transition: height 200ms`（video） | 高度不再变化，过渡是空转 |
| 居中浮层的 `top: calc((100% - 72px) / 2)` | 满幅后它们自带的 `inset:0` / `top:50%` 就是正确居中 |

`fs-anim`（进全屏 120ms 后才置位）保留下来，改成控制条自己的门闩：
`.video-wrap:fullscreen:not(.fs-anim) .fs-bar { transition: none }` —— 全屏刚建立那一帧
wrap 会从窗口尺寸跳到全屏尺寸，别让条子跟着跑一遍动效。

## 2. 玻璃配方：三层叠加，缺一层就有一类画面翻车

```css
.fs-bar {
  background: linear-gradient(180deg,
      color-mix(in srgb, #070a10 30%, transparent) 0%,
      color-mix(in srgb, #070a10 55%, transparent) 100%);
  backdrop-filter: blur(22px) saturate(150%) brightness(0.55);
  border-top: 1px solid color-mix(in srgb, #fff 14%, transparent);
  box-shadow: inset 0 1px 0 color-mix(in srgb, #fff 6%, transparent);
}
```

| 层 | 参数 | 解决什么 |
|---|---|---|
| ① 背景模糊 | `blur(22px)` | 抹掉画面细节。**细节是可读性的头号杀手**：一条电线、一行字幕正好穿过 `00:12`，光靠半透明底怎么调都救不回来 |
| ② 压暗 | `brightness(0.55)` | 把背后亮部整体压到中低亮度。白场画面（雪景、纯色片头）下只做半透明底只有 3.6:1，压暗后才够 WCAG AA |
| ③ 半透明底 | 上 30% → 下 55% | 上沿透一点，画面透得上来，条子不切断构图；下沿实一点，控件与文字都坐在这一侧 |
| ④ 补饱和 | `saturate(150%)` | ②会顺手把颜色洗灰，补回来才像「有色玻璃」而不是一层灰纱 |

为什么不是「全透明 + 只靠 blur」：blur 只能抹平**细节**，抹不平**整体亮度**。一块
纯白画面糊成一整片白，白字照样消失。所以压暗不能省。

为什么不是「80% 不透明」：那就退回实体条了，`backdrop-filter` 变成纯开销。30%–55%
是「一眼能看出画面在动」的上限，也是「白场压得住」的下限。

## 3. 可读性保底：墨色 + 阴影 + 轨道对比

玻璃背后是任意画面，全局 `--text-dim`(#9aa5b8) 是按「恒暗面板」定的，压在画面上
只剩 2.3:1。所以条内单独一套墨色（定义在 `.fs-bar` 上，子元素只引用）：

```css
--fs-ink:        color-mix(in srgb, var(--text) 94%, transparent);  /* 标题 */
--fs-ink-dim:    color-mix(in srgb, var(--text) 80%, transparent);  /* 时间 / 图标 / 按钮 */
--fs-ink-faint:  color-mix(in srgb, var(--text) 62%, transparent);  /* 集数 */
--fs-ink-shadow: 0 1px 2px rgb(0 0 0 / 0.55);
```

**最坏情况推算**（纯白画面，`brightness(.55)` 后 140，再叠底色）：

| 位置 | 合成背景亮度 | 前景 | 对比度 |
|---|---|---|---|
| 条上沿（alpha 30%） | 101 | `--fs-ink` | **4.7:1** ✓ AA |
| 条下沿（alpha 55%） | 69 | `--fs-ink` | **7.7:1** |
| 控制行（alpha≈45%） | 76 | `--fs-ink-dim` | **5.4:1** ✓ AA |

真实画面经过 `blur(22px)` 后极少出现整块纯白，所以这是**下界**。`--fs-ink-shadow`
是最后一道保险：遇到极端亮部（雪、白场片头）时靠它把字形从背景里拉出来。

轨道同样提了一档：未播部分 `--text` 22% → **26%**。玻璃背后可能是亮画面，太淡的
轨道会直接消失在背景里 —— 用户看不出「这条能拖」。音量轨道同值，已播部分与
静音态分别改用 `--fs-ink-dim` / `--fs-ink-faint`。

## 4. 与整体界面风格一致

- **hover 用半透明白洗**（`#fff 12%`）而不是 `--panel-3`：玻璃上放实色块像贴了张纸，
  条子一动就露馅。`.fs-act`（选集/下一集/退出全屏）同理，改成 `#fff 8%` 底 +
  `#fff 16%` 描边 —— 看起来是浮在玻璃上的片，而不是嵌进去的块。
- **强调色仍是实色**：`.fs-act.primary`（下一集）保持 `--accent` 实底。玻璃上唯一的
  实色就是主行动，层级更清楚。
- **玻璃上沿 = 1px 亮线 + 1px 内高光**：只有亮线像贴了条白边，加上内高光才有「厚度」。
- **选集面板不跟着变透**：它是弹层，读表单需要稳定对比度，保持近实底（97%）+ blur(12px)。

## 5. 边界与已知取舍

1. **mpv 内核下玻璃背后是黑**：子窗口不能压，条子只能停在它上方，所以玻璃没有画面可采样。
   行为正确（不透明度的差别而已），不是 bug。
2. **画面下沿 72px 会被玻璃盖住**：这是「半透明压画面」的必然代价。全屏时条子 2.6s 自动
   收起，正常观看（含硬字幕）基本碰不到；一旦碰了，动一下鼠标就能把它让开。
3. **点击区域没变**：条子仍吃下自己那 72px（和改之前一致），画面其余部分的点击照旧是播放/暂停。
4. **`@supports not (backdrop-filter)` 兜底**：不支持背景模糊的环境退回 `rgb(9 12 18 / .94)`
   近实底。半透明底单独撑不起可读性，宁可丢掉玻璃感。
5. **P38 红线不违反**：`backdrop-filter` 挂在**覆盖层**上，不是 `<video>` 的祖先，
   没有给视频区加 `overflow:hidden` / `border-radius` / 祖先 `filter`。视频区仍是直角、
   不裁剪。
6. **GPU 成本**：`backdrop-filter` 要求把背后（含视频帧）先读回纹理再模糊。区域只有
   1920×72 一条，常规机器无感；但在弱核显 / 多显示器混合 GPU 上若出现掉帧，**先摘
   `blur()`、保留渐变底与压暗**（`brightness` 是 `filter` 函数里最便宜的一个），
   视觉退化最小。探针是软件渲染跑的，验不出这条 —— 真机掉帧才需要动。

## 6. 怎么复核（回归口径）

探针 `.probe/p54-fullscreen.mjs` 新增 `glass` 段，三个硬指标：

```
backdrop   = "blur(22px) saturate(1.5) brightness(0.55)"   # 必须含 blur，不能是 none
bgImage    = linear-gradient(... /0.3 → /0.55)             # 底色必须是渐变/半透明
overlapPx  = 72     # 玻璃压在画面上（=0 说明画面又让位了，模糊等于没做）
videoBottomGap = 0  # 画面满幅
```

外加 `idle` 七态里 `videoH` 恒为 1080（收起不再改画面高度）。

肉眼复核用 `.probe/crop.cjs` 裁条子区域（顺带打印亮度 min/mean/max）：

```bash
electron .probe/crop.cjs '{"src":".screenshots/p54/fs.png","x":0,"y":985,"w":1920,"h":95,"scale":1.5,"out":".screenshots/p54/bar-glass.png"}'
```

要调手感就动三个旋钮：`blur` 半径（细节压制力度）、`brightness`（白场兜底强度）、
渐变两端 alpha（玻璃感 vs 读得清）。**三个一起调**，只动 alpha 会在亮画面上翻车。
