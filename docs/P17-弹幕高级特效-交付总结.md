# P17 弹幕高级特效（发光 / 渐变 / 图片）交付总结

> 2026-10-27 交付。本批解决 P14 遗留的「mpv 内核弹幕只有 ASS 纯文本」能力缺口。

## 1. 需求与方案选型

P14 弹幕在 libmpv 内核下走 ASS 字幕（libass 渲染），存在两个硬限制：

- **图片弹幕不可能**：libass 不支持在字幕里嵌位图；
- **发光/渐变表达力弱**：ASS 的 `\blur`/`\bord` 只能近似，且无法做逐弹幕的彩色渐变填充。

**选型：透明覆盖层窗口（透明 + 无边框 + owner 挂主窗口的 BrowserWindow）**，在覆盖层里用与 hls 路径**同一套** `DanmakuEngine`（Canvas 2D）画弹幕。

为什么可行：mpv 视频表面是主窗口的 Win32 子窗口（`WS_CHILD`），恒在父客户区之上；而 Windows 的 **owned window 恒浮在 owner 之上**（连同其子窗口）—— 覆盖层因此能盖住 mpv 画面。这是窗口 Z 序模型给的路，不是渲染技巧。

## 2. 特效语义（渲染侧 `danmaku/fx.ts` + `engine.ts`）

| 特效 | 实现 | 备注 |
|---|---|---|
| `glow` 发光 | `shadowColor=弹幕色` + `shadowBlur=fontSize*0.45`，fill 两遍加强密度，再补一圈半透明深色细描边保可读 | 光晕颜色跟随用户选的弹幕色 |
| `gradient` 渐变 | 横向三停 `createLinearGradient`：亮(lighten 0.55) → 主色 → 暗(darken 0.25)，随文字宽度铺满 | 不缓存 gradient 对象（键含 x/width，命中率低不值得） |
| 图片弹幕 | `text` 本身是图片 URL → 按 `drawImage` 渲染，高 = `fontSize*1.5`，宽按真实宽高比 | http(s) 走扩展名白名单（防普通链接误判成裂图）；`data:image/*` 全支持 |

关键实现点：

- **图片异步解码热替换**：spawn 时图未就绪 → 先按 1:1 占位宽分配轨道；渲染帧里发现 `imgUrl` 对应缓存已解码 → 就地替换位图 + 重算宽度（静止弹幕的居中 x 随之修正）。不做这一步，图片弹幕会永远停在「URL 文本兜底」。
- **加载失败兜底**：裂图按原文本（URL）绘制，比静默消失可诊断；图片缓存上限 120 条防刷内存。
- **fx 白名单**：只认 `glow`/`gradient`（Rust `normalize_fx` + 前端 `normalizeFx` 双侧校验），脏值静默归普通。
- **hls 内核同样受益**：特效在 `DanmakuEngine` 里实现，hls 的 Canvas 层天然支持；覆盖层只是让 mpv 也能吃到同一引擎。

## 3. 数据链路

- **存储**：`danmaku` 表加 `fx TEXT` 列（`MIGRATIONS` 补列，旧库 ALTER duplicate column 忽略）。出参 `fx` 为 `None` 时**省略字段**，与旧版本协议完全兼容。
- **发送**：`danmaku.send` 加 `fx` 参数 → 白名单校验 → 落库；`list`/`fetch` 回读。去重语义不变（UNIQUE 键不含 fx：同内容换样式重发会被既有去重吸收）。
- **ASS 兜底不受影响**：`danmaku.ass` 忽略 fx —— 覆盖层关掉时 mpv 仍走 ASS 纯文本，两条路径互斥（前端保证不同时启用，防双重弹幕）。

## 4. 覆盖层窗口（`electron/main/overlay.ts`）

- **窗口参数**：`transparent + frame:false + focusable:false + skipTaskbar + type:'toolbar'`，`setIgnoreMouseEvents(true)` 点击穿透；`parent` 挂主窗口 → 恒浮其上、随主窗口最小化。
- **跟随**：窗口尺寸恒 = 主窗口 `getContentBounds()`（DIP 与 renderer CSS px 同基准）；事件 + 500ms 兜底轮询双保险，bounds 未变不重设（防抖动）。
- **弹幕画布定位**：主窗口 renderer 上报视频区矩形（复用 mpvRect 的 ResizeObserver 管线），覆盖层内 `#dm-rect` div 定位，画布随矩形走。
- **生命周期**：惰性创建（首个 `ensure` 命令时），主窗口关闭即 `destroy()`。
- **IPC 拓扑**（三个通道）：
  - `pf:overlay-cmd`（renderer→main）：`ensure/show/hide/ready` 窗口级命令就地消化，`items/opts/duration/seek/reset/push/rect/enabled` 数据命令转发覆盖层；
  - `pf:overlay-apply`（main→overlay）：数据命令；
  - `pf:overlay-ready`（overlay→main→renderer）：覆盖层加载完成，主窗口重发全量状态（另有 1.5s 竞态兜底）。
- **时钟**：覆盖层复用 `MpvInterpolatedClock`，直接吃主进程转发来的 `mpv.state` 事件 —— 与主窗口弹幕层同一事件源，天然同拍。
- **preload 扩展**：`overlayCmd` / `onOverlayApply` / `onOverlayReady` 三个桥函数；浏览器调试模式（无 polyframe API）下全链路静默空操作。
- **构建**：`electron-vite` renderer 多页输入加 `overlay.html`；页面 CSP 放开 `img-src http: https: data:`、禁 `connect-src`（本页不联网）。

## 5. UI

- 发送栏新增样式下拉：普通 / 发光 / 渐变（`PlayerView` `dmFx` → `dm.send(..., fx)`）。
- 设置页新增开关「**mpv 高级特效弹幕（透明覆盖层窗口）**」→ `fxOverlay` 落 Rust settings（`DanmakuSettings.fxOverlay`，默认 false）。
- 开启后 `syncMpvAss` 跳过（防 ASS + 覆盖层双重弹幕）；关闭回到 ASS 路径。

调试插曲：

1. **图片弹幕曾永远显示 URL 文本** —— 根因即 §2 的异步解码热替换缺失；像素探针发现画布上「蓝色 1/3 + 黑色 2/3」才定位到两层问题（引擎热替换 + 测试 BMP 少写 2 个像素的字节）。
2. 冒烟脚本首跑大面积 FAIL 是发送限流（1.5s/条）与去重业务语义（重复 = `ok:false + kind:duplicate`）所致，非功能缺陷。

## 7. 已知边界

- 覆盖层方案仅 Windows 验证（owner Z 序是 Win32 语义；mac/Linux 的 Electron owned window 行为一致，未实测）。
- 远程图片（非 CORS、非 data URL）绘制会污染 canvas —— 弹幕画布从不读像素，无功能影响；E2E 像素断言用 data URL 规避。
- 全屏模式下覆盖层跟随未做专项适配（主窗口目前无全屏播放路径）。
- mpv + 覆盖层的组合需真实 libmpv 环境人工确认视觉效果；e2e 覆盖的是引擎特效与设置链路。
