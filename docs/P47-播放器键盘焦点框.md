# P47 播放器键盘快进后进度条多出一条边框

> 现象：鼠标点过进度条（或画面）之后，用键盘 ← / → 快进后退，进度条那一行外面会
> 冒出一条 1px 的浅色矩形边框；鼠标拖动、点按钮都不会出现，所以看起来像「凭空多出来的框」。

## 结论

**这条边框不是应用样式画的，是 Chromium UA 默认样式里的焦点环（focus ring）。**

| 元素 | UA 规则 | 画在哪 |
|---|---|---|
| `<video>` 自身 | `video:focus-visible { outline: auto 1px }` | 整个视频区一圈 |
| 原生控制条内部时间轴 | `video::-webkit-media-controls-timeline:focus-visible` 同款 | 进度条那一行外面 |

实测计算值（本机 Electron / Windows）：

```
video:focus-visible  →  outline: auto 1px rgb(238, 238, 238)
内部时间轴（通过作者样式注入白色对照）→ 命中 3px 白框，证明伪元素可被作者样式覆盖
```

## 触发原因：`:focus-visible` 只在键盘操作时成立

Chromium 从 M86 起按「输入模态」决定要不要画焦点环：

- **鼠标**点画面 / 点进度条 → `:focus-visible = false` → **不画框**（平时看到的就是这个状态）
- **任意键盘按下**（← → 、空格、Tab）→ `:focus-visible = true` → **立刻画框**

而焦点落在哪，决定了框画在哪一圈：

1. 点画面 → 焦点在 `<video>` 上 → 按方向键时画**整个视频区**一圈（1px，白/浅灰）
2. **点进度条 → 焦点钻进原生控制条的 closed shadow tree，落在内部
   `<input type=range>` 上** → 按方向键时画**进度条那一行**一圈 ← 用户截图的这条

第 2 种情况有个坑：`document.activeElement` 依然返回 `VIDEO`，但
`video.matches(':focus')` 是 **false**（真实焦点在 shadow 内），很容易误判成「焦点不在控件上」。

顺带确认了原生方向键的语义（12s 素材实测）：焦点在时间轴上时，**每按一次 ← / → 移动
1% 时长**（3 次 = +0.12s）；22 分钟的剧集就是每次约 13 秒 —— 所以用户感知是「快进/后退」。
焦点在 `<video>` 上时按方向键则**不动**（这也是为什么几乎必然先点过进度条）。

## 修复

`apps/desktop/src/renderer/src/components/PlayerView.vue`（scoped style，`video {}` 之后）：

```css
.video-wrap video:focus,
.video-wrap video:focus-visible {
  outline: none;
}
.video-wrap :deep(video::-webkit-media-controls-timeline) {
  outline: none;
}
```

三条约束必须遵守：

1. **两条规则分开写**。伪元素选择器一旦不被支持，会连同整条选择器列表一起失效；
   写在一起就等于「一条不支持，连视频整圈那条也没了」。
2. **内部时间轴只能用 `::-webkit-media-controls-*` 伪元素够到**。原生控件的 shadow root
   是 closed 的，`video.shadowRoot` 恒为 null，JS 和普通选择器都进不去。
3. **scoped 样式用 `:deep()`**，编译成 `.video-wrap[data-v-x] video::-webkit-media-controls-timeline`；
   写成不带 `:deep()` 的 `video[data-v-x]::...` 是否命中取决于编译结果，别赌。

只改外观，不改行为：方向键 1% 步进、空格暂停、拖动进度条、双击全屏全部照旧。

## 代价与后续选项

去掉焦点环意味着「键盘焦点在哪」不再有系统级提示。播放器这块本来就没有做键盘焦点设计，
视觉上更干净；如果哪天要补可访问性，建议加**设计过的**指示而不是还回 UA 框，例如：

- 键盘快进时在画面上闪一条「← 快退 5 秒 / → 快进 5 秒 + 当前时间」的提示条（B 站/YouTube 做法）；
- 或给 `.video-wrap` 挂 `:has(video:focus-visible)` 的 accent 描边（有意为之的样式，而不是 1px 灰框）。

## 排查要点（下次同类现象）

1. 先分辨「框是应用画的还是 UA 画的」：遍历 DOM + 递归 shadowRoot，收集
   `outline-style ≠ none` 或 `border-style ≠ none` 且 `rect` 非零的节点。UA 焦点环会以
   `outline: auto 1px` 的形式出现。
2. `outline: auto` 的颜色**不跟 CSS**，取系统强调色 —— 深色界面上表现为灰白，别以为是自己的 token 漏了。
3. 判定「焦点是不是在原生控件里」看 `host.matches(':focus')`，别只看 `document.activeElement`。
4. 像素级判定要按**行/列亮线**统计，别只截一张图看：`outline: auto` 只有 1px，缩放后会糊掉。
   注意红色系 luma≈116，用「亮度 > 140」筛会漏检 —— 反向对照要用纯白。
