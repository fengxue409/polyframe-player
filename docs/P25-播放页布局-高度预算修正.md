# P25 播放页布局修正：播放卡高度预算

> 追补 P24（单滚动容器）。用户截图反馈「当前布局有问题」，红箭头指向播放卡右下角 ——
> 那里正是**调试面板的标题被播放卡底边切成半行**的位置。

## 1. 现象

截图（1920×1009 窗口，播放页）能看到三件事：

1. 播放卡从顶栏下沿一直铺到窗口底边，占掉整屏高度，**视频本身 750px 高**；
2. 播放卡下方紧贴着「调试面板」卡，但**只剩标题上半截**，被播放卡底边横切；
3. 页面右侧出现滚动条（内容比视口高），滚到哪都躲不开 —— 调试面板永远看不全。

## 2. 取证（像素级）

用 Electron `nativeImage` 把截图逐行扫描（判据：面板底色 `#121722` / 卡片边框 `#1e2534` / 页面底色 `#0b0e14`）：

| y（物理像素） | 内容 |
| --- | --- |
| 68 | 播放卡顶边 |
| 84 – 834 | 视频区（高 750，16:9 与 1331 宽自洽） |
| 834 – 888 | 内核/倍速/弹幕按钮行 |
| 888 – 926 | 发弹幕输入行 |
| 926 – 966 | 折叠行「手动播放 / 高级」上方留白 |
| **966** | **一条通栏横线 = 调试面板卡顶边** |
| 967 – 969 | 调试面板标题「调试面板」的文字上半截 |
| **970** | **文字被切断**（此后到 991 全是播放卡面板底色） |
| **992** | **播放卡通栏底边** |
| 993 – 1009 | 页面底色 |

结论：**调试面板卡的顶边（966）比播放卡底边（992）高 26px**，也就是两块卡重叠了 26px；
播放卡 `z-index: 2`，把调试面板的标题压在下面，只露出 3px 字头。

## 3. 根因

P24 给播放卡封顶的写法是：

```css
.card.player {
  max-width: min(100%, calc((100dvh - 260px) * 16 / 9 + 34px));
}
```

`260px` 是「视口里要留给视频卡以外的东西」的预留。但真实开销是：

```
顶栏 51 + 内容上下留白 32 + 卡片控制区 174 + 与调试面板的间隙 16 + 调试面板 50 ≈ 323
```

预留 260 < 实际 323，于是**播放卡比视口还高**（1920×1009 下卡片 924 高，视口可用 958）：
一旦要看到下面的东西就得滚动，而 `position: sticky` 会把卡片钉在滚动口顶部，
后面的内容（调试面板）就从卡片底下穿过去 ——
`gapMax = -31px`（镜面复现值），表现为「标题被切半行」。

也就是说：**sticky + 卡片高度失控**，两者叠加才炸。只改 sticky 不改高度，滚动照样把面板送走；
只改高度不改 sticky，高度算错时还是同一处出血。两个都得治。

## 4. 改法

### 4.1 高度预算写成两个变量（`PlayerView.vue`）

```css
.player-view {
  --pf-card-chrome: 176px;  /* 视频区以外的卡片高度（含 mpv 变体由模板内联覆盖为 222px） */
  --pf-card-room: 194px;    /* 卡片之外的开销：顶栏 51 + 留白 32 + 间隙 16 + 调试面板 50 + 余量 45 */
}
```

### 4.2 宽度由高度反推，而不是由列宽撑满

```css
.video-wrap {
  aspect-ratio: 16 / 9;
  width: min(100%, calc((100dvh - var(--pf-card-chrome) - var(--pf-card-room)) * 16 / 9));
  margin-inline: auto;
}
```

卡片宽度不再封顶（`max-width` 从 `.card.player` 移除），**视频区**自己算宽度：
先求出「视频能用多高」，再按 16/9 反推宽度，宽高天然联动、永不超预算。
卡片底边恒在视口下方 `--pf-card-room` 处，播放卡 + 调试面板正好一屏放下，多数情况下**整页零滚动**。

### 4.3 mpv 内核单独一档预算

mpv 内核会多出一条「进度拖动 + 字幕/音轨选择」行（约 46px），
按 hls 的 176px 算就会短一截、又被 sticky 裁掉。模板里按内核写内联变量：

```ts
const cardChrome = computed(() =>
  store.engine === 'mpv' && mpvHasMedia.value ? '222px' : '176px'
)
```

### 4.4 调试面板展开时取消吸顶

```css
.player-view.debug-open .card.player { position: static; }
```

面板展开后比留出的空隙高得多，吸顶会让它从卡片底下滑过去。
展开即意味着「要看日志」，此时宁可让视频跟着页面滚走。

## 6. 已知边界

- **侧栏很长（剧集展开到几十集）+ 调试面板收起**时页面仍要滚动，
  收起的调试面板会从吸顶的播放卡底下穿过（`gapMax = −271`）。
  这是 sticky 的固有行为，且此时面板只有 50px 高、滚回一点就能看全；
  一旦展开面板就切 `static`（用例 8 已验证），不会出现「只能看到半行」的死角。
- 窄屏（≤900px）沿用 P24 的三行堆叠，播放卡本就 `static`，本次只把它多余的 `max-width` 去掉。
- 卡片额外行（错误提示 `.alert`、弹幕反馈）出现时卡片会高出预算约 40px，
  仍被 `--pf-card-room` 里的 45px 余量吸收；只有同时叠满所有可选行才可能重新溢出。

## 7. 复跑

```bash
node .layout-check/build.mjs          # 重新从 .vue 抽样式，生成 mirror.html
./apps/desktop/node_modules/electron/dist/electron.exe .layout-check/measure.js
# 结果见 .layout-check/result.json 与 shot-*.png
```

坑（已写进 `measure.js` 注释）：

- `frame: false` 在这个环境里直接 `ERR_FAILED`，别加；
- `win.destroy()` 会触发 `window-all-closed` 把 app 退掉，后续窗口全部加载失败 →
  必须自己吞掉该事件；
- 窗口比屏幕宽时会被 clamp（1904×993 而非 1920×1009），断言一律用实测 `vw/vh`；
- 目录名带空格：`loadFile` + `search` 拼出的 URL 不可靠，用 `pathToFileURL` 自己拼。
