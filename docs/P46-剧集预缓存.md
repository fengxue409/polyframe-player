# P46 剧集预缓存（窗口化）

> 需求：播放某一集时自动缓存其后的剧集；策略可选「后续 3 集 / 剩余全部 / 自定义 N 集」，
> 并明确触发时机、配置方式与「数量不足」时的处理。

## 1. 结论先说

| 问题 | 答案 |
|---|---|
| 什么时候触发 | **起播成功那一刻**（`playEpisode` 拿到任务并开始播放之后）。浏览详情、悬停海报、拉剧集列表都不触发 |
| 之后靠什么推进 | 内核 `series_queue_tick` 每 **5s** 一拍，按当前播放集重算窗口，**串行**推进 |
| 谁决定缓存多少 | 内置窗口 = 当前集之后的 N 集（`off` / `ahead` / `all`），默认 `ahead 3` |
| 数量不足怎么办 | **按实际剩余截断**，返回 `truncated=true` 如实告知，不报错、不等待 |
| 会不会抢播放带宽 | 不会：窗口内**同一时刻只跑 1 个预取**；播放中的任务永远优先 |

## 2. 触发时机（为什么不能更早 / 更晚）

```
用户点选集 → fetchDetail → task.create（起播）→ playTask → 播放器出画
                                                        │
                                                        └─ series.attach（此刻）
                                                             ├─ 同步整组剧集（集名/URL/集序）
                                                             ├─ 把当前任务挂到 series + episode_index
                                                             └─ 立即 kick 一轮窗口调度
```

- **不能更早**：`task.create` 之前用户可能还在挑线路/换片源，早预取就是白下。
  详情页浏览同理 —— 点开看一眼不等于要看。
- **不能更晚**：等到「本集播到 95%」再开始（P3 的旧行为），下一集往往还没下够，
  连播时会卡在起播上。预取的收益全在「提前」。
- **换集/换线路会再调一次**：集序与 URL 一起刷新，窗口跟着当前集前移。
- **暂停播放后**：`last_touch` 2 分钟内没有播放头活动，tick 直接返回 → 无人观看就不预取。

## 3. 可配置参数

### 3.1 三档 + 自定义

| 档位 | `mode` | `count` | 语义 |
|---|---|---|---|
| 关闭 | `off` | — | 只保留 P3 旧行为：本集 ≥95% 时顺延缓存下一集 |
| 后续 3 集 | `ahead` | 3 | 默认值；只缓存紧邻的 3 集 |
| 剩余全部 | `all` | — | 当前集之后的全部（长剧会持续占用带宽与磁盘，受容量上限约束） |
| 自定义 N 集 | `ahead` | 1..50 | 上限 50，再多没有带宽意义 |

### 3.2 设置方式

- **UI**：设置 → 播放与缓存 → 「剧集预缓存」下拉 + 自定义集数输入 + 保存。
- **RPC**：
  - `config.get_series_prefetch` → `{ mode, count }`
  - `config.set_series_prefetch { mode?, count? }` → 同结构（只写传入字段）
- **落库**：`settings` 表 `series.prefetch_mode` / `series.prefetch_count`（重启保持）。
- **生效时机**：保存后**下一次 tick（≤5s）**即生效，不必重启、不必重新起播。
  窗口是每拍重算的，所以档位可以从 3 改到 10、或从 all 改回 off，在跑的预取会按新窗口收放。

### 3.3 与「默认缓存档」的关系

预取任务**固定按 `precache` 建**（`stream/online` 下「预缓存」是自相矛盾的）。
用户之后亲自播这一集时，仍按他自己的「新建任务默认档」覆盖（P29 规则不变）——
即：预取只负责把它下下来，档位最终归用户。

## 4. 窗口算法

```rust
pick_window(mode, count, current, available) -> Vec<idx>
```

- 只取 `idx > current` 的集（不回头缓存已经播过的）。
- `available` 来自 `series_episodes`（前端起播时同步的整组剧集），**允许空洞**：
  前端只传了部分集、或某集失败被剔除，都不影响其它集入选。
- `ahead` 取前 `count` 个；`all` 全取；`off` 返回空。

### 4.1 「数量不足」的四种情况

| 情况 | 处理 |
|---|---|
| 剩余集数 < N | 窗口截断到实际剩余；`truncated=true`，UI 显示「剩余不足，已按实际集数」 |
| 已到最后一集 | 窗口为空，不建任务、不报错（日志只记一次） |
| 集序有空洞（缺第 5 集） | 跳过缺失集，继续取后面的（不把窗口长度当集号） |
| 该剧只有 1 集 / 前端没给 episodes | `queue.length < 2` 时前端根本不发 attach；内核收到空 episodes 时窗口为空 |

### 4.2 调度：串行，不做并发预取

`dispatch_window` 每拍只挑**窗口内最早一个未完成**的集：

```
窗口 = [3,4,5]
第 3 集 caching → 停（4、5 排队）
第 3 集 ready   → 看第 4 集 → 起
第 3 集 paused  → 跳过（尊重用户手动暂停）
第 3 集 failed(达上限)/退避中 → 跳过，允许第 4 集继续推进
```

**为什么串行**：下载 job 与播放共用同一条出网带宽。并发 3 个预取会把正在播的那一集
拖成卡顿，而「播放不卡」的优先级高于「多存几集」。

**滑出窗口即停**：用户切到下一集后，旧窗口里还在跑的预取会被 `stop_download_job`
停掉（协同收尾，不硬杀），把带宽让给新窗口。

## 5. 失败与退避

- 单集失败记 `attempts+1` + `last_error` + `next_try_at`（60s / 5min / 15min）。
- 第 **3** 次失败后不再自动重试（`state=failed`），日志留痕；用户自己播这一集仍会正常解析。
- 任务状态同步对齐真相：可重试 → `pending`（任务页「准备中」，下一拍会再来）；
  达上限 → `failed`（任务页「失败」）。**不能只把错误塞进 `probe_errors`**——
  那样任务行会永远停在 pending，侧栏一直显示「排队中」而窗口其实已放弃。
- 失败集不阻塞窗口：后面的集继续推进（一部剧里一集死链不该堵死整季）。
- 预取失败**永远不影响播放**：`series.attach` 是 fire-and-forget，异常只落日志。

## 6. 与既有机制的关系

| 机制 | 关系 |
|---|---|
| P3 顺延（播完 95% → 下一集） | `off` 档保留；`ahead/all` 下由窗口天然覆盖（窗口恒含 current+1），不再单独跑 |
| P40 单一下载槽 | 不冲突：预取只「起 job」，不占播放槽；播放优先的语义不变 |
| P19/P29 缓存档 | 预取任务固定 `precache`；用户播放时按默认档覆盖 |
| 清理器（容量/播完 TTL/未播完 LRU） | 预取任务与普通任务一视同仁，超容量按「最久未播放」淘汰；预取不等于永久保留 |
| 任务页分组 | 预取任务显示为「准备中/下载中」，与手动任务同源（`task.list` 里就是普通任务） |

## 7. 数据结构与 RPC

```sql
-- 前端起播时同步进来，内核自己没有片源详情
CREATE TABLE series_episodes(
  series_id TEXT NOT NULL, idx INTEGER NOT NULL, name TEXT, url TEXT NOT NULL,
  attempts INTEGER NOT NULL DEFAULT 0, last_error TEXT, next_try_at INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY(series_id, idx)
);
```

- `series.attach { seriesId, title?, taskId?, index, episodes:[{index,name,url}] }`
  → 返回窗口状态（见下）。`seriesId` 由前端拼 `${sourceId || api}:${vodId}`（同一部片在不同站是不同剧）。
- `series.prefetch_status { taskId }` → 窗口状态（只读，播放页侧栏 5s 刷一次）：
  `{ seriesId, mode, count, current, total, remaining, truncated, items:[{index,name,taskId,state,attempts,error}] }`
- `state`：`queued`（还没建任务）/ `caching`（解析或下载中）/ `ready` / `paused` / `failed`。

## 8. 边界与已知限制

- 预取窗口**只看当前播放集**：同时追两部剧时，只有最近有播放头的那部在预取（单窗口，不并行）。
- 预取任务同样受 `fetch_text` 的重试链影响：源站慢时一集要 30–70s，`all` 档下长剧会排很久。
- 集序按前端传入的 `index` 用；换线路后集数对不齐时以最后一次 attach 为准。
- 预取不区分「已看过」：回看老剧时窗口仍会按当前集往后取（符合「继续看」的直觉）。
