# P33 视频缩略图加载 + 按视频维度聚合

> 目标：媒体库不再「一条任务一张卡」，而是「一部片一张卡」；同一部片的多张封面
> 归并到这张卡里，不重复、不分散。

## 1. 为什么需要动后端

前端拿不到「同一部片的多张缩略图」——这是本次改动的起点：

| 数据源 | 有没有封面 | 有没有「多张」 |
|---|---|---|
| `favorites.poster` | 有，一张 | 否 |
| `play_history.poster` | 有，一张 | 否 |
| `tasks` | **完全没有封面字段** | 否 |
| `favorite_sources` | **原设计没有 poster 列** | 同一部片在 A/B/C 站各有自己的海报 |

同一部影片在不同采集站的海报往往不是同一张图。把 `poster` 补到片源维度，
「一个视频有多张缩略图」才有真实数据基础。

**改动**（`apps/core/crates`）：

- `catalog_store.rs`：`favorite_sources` 建表加 `poster TEXT`；
  `FavoriteSourceRow` / `insert_favorite_source` / `update_favorite_source_episodes`
  全程透传；`find_favorite_source_by_site`、`list_favorite_sources` 的 SELECT 同步加列。
- `pf-engine/src/lib.rs`：`MIGRATIONS` 加 `ALTER TABLE favorite_sources ADD COLUMN poster TEXT`，
  旧库自动补列（新库建表已含）。
- `catalog.rs`：`fav_source_json` 输出 `poster`；`favorite_from_detail` 写入 `d.poster`；
  追更巡检 `favorite.refresh` 回写时顺带刷新 `item.vod_pic`（站换了海报能跟上）。
- `netdisk.rs` / 手动补片源：显式传 `None`（网盘没有封面）。
- `packages/shared`：`FavoriteSource.poster?: string`。

## 2. 数据结构

### 2.1 缩略图

```ts
interface VideoThumb {
  url: string    // 原始 URL（可能带签名，不能用去重键代替去请求）
  key: string    // 归一化去重键
  source: string // 「收藏封面」/「站A」/「播放记录」
}
```

`key` 由 `thumbKey(url)` 生成，归一化三类源站写法：

| 输入 | key |
|---|---|
| `https://img.x/a.jpg` | `https://img.x/a.jpg` |
| `https://img.x/a.jpg@720w.jpg` | `https://img.x/a.jpg` |
| `https://img.x/a.jpg?x-oss-process=image/resize,w_300` | `https://img.x/a.jpg` |
| `https://img.x/a.jpg#poster` | `https://img.x/a.jpg` |
| `https://img.x/a.jpg?sign=abc` | **保留 query**（签名不同就是不同资源，合并会 403） |

### 2.2 视频组

```ts
interface VideoGroup {
  key: string           // fav:<id> / hist:<hkey> / dir:<host+dir> / url:<归一化>
  origin: 'favorite' | 'history' | 'series-dir' | 'single'
  title: string         // 多集组是片名（去掉「第 N 集」），不是第一条任务的标题
  subtitle: string      // 来源站（最多 3 个）/「N 个任务」
  thumbs: VideoThumb[]  // 去重后，[0] 是封面
  tasks: Task[]         // 组内任务，新的在前
  favoriteId?: string
  status: 'active' | 'done' | 'failed'
  updatedAt: number
}
```

`status` 语义：有任务在跑 → `active`；否则**只要有一个失败就报 `failed`**
（不能因为同组别的任务成功就把失败藏起来）；全就绪才是 `done`。

## 3. 聚合逻辑：只做有证据的合并

`buildVideoGroups()` 对每条任务按下面顺序判定归属，命中即停：

| 优先级 | 证据 | 键 | 说明 |
|---|---|---|---|
| 1 | 任务 URL 精确命中某条收藏的剧集 URL | `fav:<id>` | 最强。跨站两集也能并到一起 |
| 2 | 标题归一后与某个收藏名完全相同 | `fav:<id>` | 名称完全相等，不做模糊匹配 |
| 3 | URL 命中播放历史 | `hist:<hkey>` | 直链/网盘类没有收藏时的兜底 |
| 4 | URL 的**集数目录**相同 | `dir:<host+dir>` | 纯结构证据，见下 |
| 5 | 以上都不成立 | `url:<归一化 URL>` | 独立成组 |

### 3.1 集数目录的判定条件

`seriesDirKey('https://cdn.x/剧A/S01/E02/index.m3u8') → 'cdn.x/剧A/S01'`

只有**被剥掉的目录末段确实是集数标记**时才返回键：

- 匹配：`01` / `EP03` / `E12` / `第5集` / `第 3 期` / `S01E02`
- 不匹配：`/uploads/a.mp4`、`/abc/v1/v.m3u8` → 返回 `null`，各自独立

这条限制是刻意的：`/uploads/` 下几百个不相关视频如果按目录聚类，会被错误并成一部片。

### 3.2 刻意不做的两件事

- **不做模糊标题聚类**。《流浪地球》和《流浪地球2》归一到 `流浪地球` 和 `流浪地球2`，
  不相等就不合并。P32 的教训是靠标题猜剧名，错并比不并更难发现——用户看到「这是同一部片」
  却播不了对应集数，会以为丢数据。
- **不做「URL 相似度」**。不同 CDN 的地址长得像不代表是同一资源。

### 3.3 中文路径必须解码

`new URL().pathname` 是百分号编码的，`/剧A/S01/` 拿到的是 `/%E5%89%A7A/S01/`。
不 `decodeURIComponent` 的话，同一条路径的编码/未编码两种写法会算出两个键，
聚合直接失效（本地回归一开始就是这条挂了）。

## 4. 缩略图加载器

`lib/thumb-loader.ts` —— 与框架无关的单例，解决四个浏览器层面的问题：

| 机制 | 取值 | 原因 |
|---|---|---|
| 懒加载 | `IntersectionObserver`，`rootMargin: 240px` | 一屏几十张封面不能同时发请求 |
| 并发闸门 | 6 路 | 代理单张几百 KB，本地回环 6 路已够吃满 |
| in-flight 去重 | 按 `thumbKey` 排队 | 聚合后同一张图会被多张卡复用 |
| 内存记录 | 400 条 LRU | 滚动来回不重复请求 |
| 失败退避 | 10 分钟 + 重试 1 次 | 图床挂了不能重试风暴 |
| 落盘 | **不做** | `/pic/` 代理已有 `src_cache(poster)` + `Cache-Control: max-age=86400` |

失败回退：`state === 'error'` 时卡片渲染占位色块（色相 = 标题哈希）+ 标题前两字水印，
沿用 P32 的视觉，不会出现破图或空白。

## 5. 界面

`LibraryView.vue` 的「下载内容」tab：

- 一张卡 = 一个视频。封面 2:3，左上角 `N 集`，左下角 `+N`（多图），右下角播放键（常驻）。
- 点 `+N` 展开缩略图条：2 列网格，每张图下方标来源（收藏封面 / 站A / 站B）。
- 多任务组显示「查看 N 集」，展开后逐集：整行点击播放，右侧 `×` 移除。
- 筛选/计数改到**组**维度：`进行中` 统计「有几部片在下载」，不再出现
  「chip 说 3、下面只有 1 张卡」的自相矛盾。
- tab 计数改为视频数（`下载内容（4）`），与 chip 的「全部 4」一致。

### 5.1 两个 CSS 坑

1. **`.vg` 必须 `min-width: 0`**。grid 的 `1fr` 是 `minmax(auto, 1fr)`，`auto` 取内容最小宽度：
   卡片里只要有不可换行的内容（长集名/URL），列就被撑宽，同一行卡片宽度与封面高度全参差。
2. **任务行的中文名必须 `white-space: nowrap`**。中文默认可在任意字符间断行，
   窄卡里会被压成一列竖排字（实测每行只有一个字）。

## 7. 已知限制

- **跨站同一部片必须先进收藏**才能合并。没收藏时只能靠集数目录（同站）或播放历史。
  想让「任意两条直链任务」合并，需要更可靠的片名来源（TMDB 或站点 detail），当前不做。
- **收藏的片源海报只对新写入生效**。旧库的 `favorite_sources` 该列为 `NULL`，
  要等追更巡检（`favorite.refresh`）刷到才会补上；`favorites.poster` 仍然可用作封面。
- 缩略图只有竖版海报一个来源，没有横版剧照（`vod_pic_slide` 未解析）。
  若后续要「一部片一排剧照」，扩展点在 `parse` 侧加字段，前端 `VideoThumb` 已支持多张与来源标注。
- 组内任务超过 ~10 条时卡片会很长，当前不做折叠（列表本身是用户主动展开的）。
