## 2. 实现要点

### 候选匹配 UI（只补 UI，链路 P14 已通）

store 层的 `searchCandidates()` / `switchEpisode(episodeId)` P14 就已实现，缺的只是渲染。`DanmakuLayer.vue`：

- 角标 `errorKind === 'no_match'` 时点击不再跳设置页，改为打开面板并自动 `searchCandidates()`；
- 面板列出 `DanmakuEpisodeCandidate{episodeId, animeTitle, episodeTitle, animeType}`，点选即 `switchEpisode`（`force:true` + `episodeId` 重拉并绑定）；
- 搜索失败/空候选有明确文案（提示检查凭据）。

**接手补齐的三点**（原实现只能「按当前片名搜一次」）：

- **改关键词重搜**：面板里加了输入框，`danmaku.match` 新增 `query` 参数（**原样送搜索**，不做片名归一化 —— 归一化会把用户精确输入的关键词改坏）。这一条是「手动指定」的核心价值：自动匹配失手最常见的原因就是片名带字幕组前后缀，不能改词就等于没法救。
- **`episodeNo` 显式指定**：可以找「同一部剧的某一集」，覆盖从集名推断的结果。
- **仅本地弹幕**：面板底部一键 `provider=local`，给「有本地/导入弹幕但不想连网」的用户一条出路。
- 播放页控制条新增常驻「源」按钮（`.dm-src`），不必等自动匹配失败才想起能改。

### 屏蔽词（过滤在出参侧，库中全量保存）

- **模型**（`pf-danmaku/src/model.rs`）：`is_blocked`（大小写不敏感子串）、`sanitize_blocked_words`（trim / 去空 / 去重 / 单词 50 字 / 总数 200 上限）。
- **设置**：`DanmakuSettings.blockedWords: Vec<String>`（serde default，旧配置平滑升级，`clamp()` 统一清洗）。
- **生效点 = 内核出参侧统一关卡 `filter_blocked`**，覆盖三条渲染路径：
  - `fetch`（本地/缓存/降级/新拉各分支的返回 items，UI 计数同步按可见条数）；
  - `list`（导入后重读、屏蔽词变更后重读都走这里）；
  - `ass`（libmpv 路径没有前端渲染层，必须在导出时过滤）。
- 库里存**全量**：改屏蔽词后不需要重新拉取/重新导入，历史频道 `reloadList` 即时生效。
- 设置页：textarea 每行一词，失焦保存；store 检测到 `blockedWords` 变化后 **await** 重读当前频道。

### 本地导入（`pf-danmaku/src/import.rs`，纯逻辑 17 单测）

- **格式探测**：`<` 开头 → XML；`{`/`[` 开头且整体可解析 → JSON。不做字节切片（见 §5）。
- **B 站 XML**：手写扫描（不引 XML 库），`p = time,mode,size,color(十进制),...`；XML 实体反转义含 `&#x4E2D;`/`&#39;` 数字引用；只认 `<d ` 后跟空白/`>`（不会误吞 `<div>`）；坏条目（时间非法/空文本/超长）跳过不报错。
- **弹弹play JSON**：`comments[].p = time,mode,color,user` + `m` 文本；**也吃顶层数组**与平铺字段（`time`/`text`/`mode`/`color`），`time` 允许是数字字符串。
- 公共管线：`sanitize_text` 逐条净化 → `dedup_sorted`（0.01s + 文本 + 模式去重）→ `make_id("import", ...)` 稳定 ID（重复导入靠 DB 唯一约束幂等吸收）→ 条数上限 `MAX_BATCH_ITEMS=8000`。
- **RPC `danmaku.import`**：参数 `{content, channelId?|title/episode}`；content 上限 8MB；导入目标 = 当前播放频道（与在线弹幕**并存显示**，不覆盖频道已有的在线匹配信息）；返回 `{imported, total, blocked}`，`blocked` 是「本次导入里当前被屏蔽词挡住的条数」（**已入库**，只是不显示）。
- **前端**：播放页发送栏「导入」按钮 → 隐藏 file input（`.xml/.json`）→ `file.text()` → `dm.importLocal(content)` → 成功后 `reloadList()` 刷新时间轴。

### ASS 临时文件治理（P14b-4）

libmpv 路径每集生成一个 `<channelId>.ass`，一个季 24 集就是 24 个文件，换片源/改剧名还会再生成一批 —— 长期运行无上限堆积。

- **双限自动清理**：`clean_ass_cache(dir, keep, max_age)` —— 按 mtime 保留最新 `ASS_KEEP_FILES=60` 个，且删除超过 `ASS_MAX_AGE_SECS=7 天` 的。**每次写完 ASS 顺手跑一次**（目录里就几十个文件，扫一遍开销可忽略），省掉「另外找个时机清理」这件永远会被忘掉的事。
- **手动清理**：`danmaku.cache.clean {keep?, maxAgeHours?}`，`keep: 0` 即清空；返回 `{removed, freed, files, bytes}`。
- **占用统计**：`danmaku.stats` 增加 `assCache: {files, bytes}`；设置页显示「N 个 · X KB」+「立即清理」。
- 只处理 `.ass`，不动目录里的其他文件（单测钉住）。

## 5. 实测踩坑

- XML 扫描第一版把「相对 `rest` 的下标」拿去切了 `content`——首条之后的文本全部错位（把 `<chatserver>` 正文并进了弹幕文本、且死循环产出重复条目）。切片基准必须与扫描基准同层。
- 屏蔽词选择「出参过滤」而非「落库时删」：否则清空屏蔽词后历史弹幕找不回来。代价是 ASS 条数与 DB 总数不同——UI 计数一律按可见算，保持一致。
- **字符串切片按字节，不按字符。** 见 §6 第一条。

## 6. 接手 review 修掉的五个缺陷

本批由两个会话接力完成，第二棒先 review 再补缺。以下五个是按严重度排序的真实缺陷：

| 编号 | 严重度 | 问题 | 后果 | 修法 |
|---|---|---|---|---|
| P14b-R1 | 🔴 崩溃 | `detect_format` 用 `&content[..content.len().min(8192)]` 取前缀。UTF-8 汉字占 3 字节，第 8192 字节落在字符内部时切片 **panic** | 导入**任何**中文弹幕文件（>8KB）都会让内核进程崩溃 —— 不是"报错"，是 panic 退出。中文文件命中概率约 2/3 | 改为先判首字符类型（`<` / `{` / `[`），**完全不做字节切片**；加回归单测构造「8192 落在汉字中间」并断言不 panic |
| P14b-R2 | 🔴 数据丢失 | `import` 分支先 `filter_blocked` 再 `insert_danmaku_batch` | 被屏蔽词命中的弹幕**根本没入库**。用户之后清空屏蔽词，那些弹幕回不来（只能重新导入）。这与 §5 自己写的「出参过滤」原则直接矛盾 | 导入全量入库，过滤只在 `fetch`/`list`/`ass` 三个出口做；返回值新增 `blocked` 计数说明「本次有多少条暂时看不见」 |
| P14b-R3 | 🟡 体验 | `saveSettings` 里屏蔽词变更后 `void this.reloadList()`（不等待） | 改完屏蔽词，条数要过一拍才跳变，用户会以为设置没生效。E2E 也因此拿到中间态 | 改成 `await`：低频操作，等一次读库没代价，换来「改完即一致」 |
| P14b-R4 | 🟡 兼容 | `attr_value` 用 `split_whitespace` 解析属性、只支持双引号 | `p = "1,2,3"`（等号带空格）与 `p='1,2,3'`（单引号）都解析失败，整份文件报"没有可导入的弹幕" | 加严格/宽松两遍解析（`squeeze_eq_spaces` 压掉等号两侧空白），单双引号都支持 |
| P14b-R5 | 🟡 兼容 | JSON 只认 `{"comments":[...]}` | 顶层数组 `[{time,text}]` 这种最常见的导出格式被判"无法识别" | `detect_format` 改成「`{`/`[` 开头且整体可解析即 JSON」；行解析支持 `p/m` 与 `time/text/mode/color` 两套字段 |

## 7. 后续（仍未排期）

- ASS 路径的发光/渐变/图片弹幕（需透明覆盖层窗口方案，成本高）。
- 屏蔽词目前是**子串匹配**，没有正则与「按发送者屏蔽」；如果需要，`is_blocked` 是唯一改动点。
- 导入上限 8000 条（`MAX_BATCH_ITEMS`）：热门番一集可能超过，超出部分静默截断，UI 尚未提示条数被截。
- `import` 在未传 `channelId` 时会退回 `channel_id("local", title, episode)` 派生频道 —— 与播放中的 `dandanplay-xxxx` 不是同一个频道，导入后当场看不到。前端已强制传 `channelId`，但这个默认值本身是个坑，建议改成「必须显式传」。
- 网盘 P9b 的「后续方向」（真实账号联调 / 百度分享转存 / 收藏续播打通 / 多账号同名合并）依旧未排期，见 `docs/P9b-网盘视频源-交付总结.md` §9。
