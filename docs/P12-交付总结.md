# P12 交付总结：磁力/BT 片源（GYING 吸收清单收官）

> 磁力作为**第五种片源**接入（m3u8 / 直链 / P2SP 多源 / 网盘 / 云解析之外）。
> 记忆点：只在**下载完成后播放** —— 这是取舍，不是缺失。

## 1. 为什么是 librqbit

| 方案 | 结论 |
|---|---|
| **librqbit 9（纯 Rust）** | ✅ 采用。无 C++ 依赖、无 libtorrent DLL 分发负担；`create_torrent` 还能本地做种，让测试完全不依赖公网 |
| libtorrent-rasterbar 绑定 | ❌ 额外 DLL + MSVC 编译链，Windows 分发与签名成本都上去了 |
| 自研 BT 协议栈 | ❌ DHT/uTP/扩展协议工程量远超一期 |

## 2. 为什么不做边下边播

MP4 的 `moov` 原子常在文件末尾、MKV 的 cues 索引也在末尾。顺序下载时播放器一 seek 就落到还没下载的区间 —— 表现是黑屏或直接报错。

所以本版承诺：**下载完成后播放**。界面把「获取元数据 → 下载中 xx% → 已完成 → 可播放」讲清楚，不给一个时灵时不灵的播放按钮。要边下边播，得先做「按播放头优先级调度分片 + moov 预取」，那是另一期的事。

## 3. 分层

```
磁力链接 / info hash / .torrent 地址
        │
        ▼  pf-magnet::magnet::normalize_magnet   （纯文本归一，9 个单测）
   规范 magnet URI
        │
        ▼  pf-magnet::engine（librqbit 会话）    （DHT 失败自动降级；45s 元数据上限）
   元数据 → 文件列表 → pick_video_file 挑正片 → only_files 只下这一集
        │
        ▼  pf-core::magnet（RPC 编排 + 每秒进度落库）
   magnet_tasks 表（跨重启保留「下过什么」）
        │
        ▼  pf-proxy /bt/{token}/{id}/{idx}      （按 Range 读盘，256KB 流式）
   播放器（<video> / libmpv 均可）
```

## 4. 接口面（8 个 RPC）

| RPC | 关键点 |
|---|---|
| `magnet.add {url, onlyFile?, initialPeers?}` | 立即返回（元数据后台等）；同 `info_hash` 直接复用；`initialPeers` 支持内网/私有种子直连（绕过 DHT 与 tracker） |
| `magnet.list` | 带 `files` 数组与进度；进度每秒落库，前端 1.5s 轮询 |
| `magnet.files` / `magnet.select` | 多集种子换集（只下选中那集） |
| `magnet.pause` / `resume` / `remove {deleteFiles?}` | 删除可连数据一起删；remove 后 `/bt` 归档 404 |
| `magnet.play` | 只在 `status=done` 时给 `/bt` 地址，否则明确报「还没下完（xx%）」 |

存储：`pf-engine::magnet_store`（表 `magnet_tasks`，含 `files_json` 供选集、`file_path` 供播放）。

## 5. 实测暴露并修掉的四个问题

1. **DHT 起不来会让整个磁力功能不可用** —— 沙箱/防火墙下 `error initializing persistent DHT`。改为降级成「无 DHT 会话」（tracker / initialPeers 仍可用）并打日志。
2. **`info_hash` 被空串覆盖** —— 元数据回填时传 `""`，导致「重复添加同一磁力」去重失效，进而触发 librqbit `input address stream exhausted`。SQL 改 `CASE WHEN ?3='' THEN info_hash ELSE ?3 END`。
3. **重启后界面永远「下载中 0%」** —— 句柄只在内存。启动时把未完成任务标为 `paused` 并说明「请重新添加；已下完的仍可播放」。
4. **列表不刷新** —— 前端轮询原本在「没有活动任务」时自停，任务从别处产生后就再也看不到。改成页面挂载期间持续轮询。

## 7. 边界与后续

- **不做磁力搜索站**：只处理用户粘贴的链接，不内置资源索引。
- **下载中会向外上传分片**：BT 协议本身决定，无法配置成「只下不传」，界面文案已说明。
- **不做种子市场 / 云端做种**：会话随应用生命周期。
- 后续可选：① 边下边播（播放头调度 + moov 预取）② 限速 / 定时策略 ③ 下载完成自动入库媒体库。
