## 3. Rust 侧改动（pf-core + pf-engine）

### 3.1 新增 RPC（协议定义见 [packages/shared](../packages/shared/src/index.ts)）

| 方法 | 语义 | 要点 |
|---|---|---|
| `task.pause` | 暂停任务下载 | `pause_task` = `stop_download_job` 协同停 worker + **700ms 收尾窗口**（防最后一次进度心跳把 Paused 覆盖回 Downloading）→ DB/内存/通知三处 paused；播放不受影响（proxy 未命中仍实时回源） |
| `task.resume` | 恢复任务下载 | `resume_task` 复用剧集队列激活管线 `activate_task`；**新增 media-in-memory 快捷分支**：会话内暂停跳过重新解析直接 spawn job；core 重启后走 `probe_and_start` 全量续传；online 模式拒绝（无预取可恢复） |
| `task.delete` | 删除任务 | `delete_task` = 停 job → `purge_task_cache`（文件+分片索引）→ `delete_task_cascade` 级联删库行（tasks/sources/segments）→ 清内存五表 + last_touch；返回 `freedBytes`；删后同 URL 可重建（UNIQUE url 不再冲突） |

- `TaskStatus` 枚举新增 `paused`（serde 双端同构，shared TS 同步）
- pf-core main.rs 分发三方法，参数校验 `taskId` 必填

### 3.2 启动恢复全量化

- `CacheStore::all_tasks()`（全行，含 ready/paused 的 status+title）替代 `unfinished_tasks()` 驱动 `restore_from_db`
- ready 任务：仅重建内存任务表（媒体库跨重启可见），不起 job
- paused 任务：保持暂停、跨重启保留（未完结查询 WHERE 不含 paused）
- 未完结任务：照旧重新解析续传
- `probe_and_start` 补 **title 透传**（restore 重建的任务 upsert 不再置空标题）+ **探测期间已暂停则不 spawn job**

## 4. 关键修复：P2.5 潜伏 bug（本轮冒烟暴露）

**现象**：P5 冒烟 `task.resume` 后任务从 `task.list` 消失（恢复约 2s 后被删）。

**根因**：`finish_job` 把 `retain_ms()` 返回的**时长**（86400000 = 1 天）当**绝对时刻**传给 `store.mark_finished(task_id, now, retain_until)` → `retain_until` 写成 1970-01-02 → 60s 周期的清理循环把刚播完的任务判为过期删除。

**为何两阶段未暴露**：cleanup 单测传的是 `now + 86_400_000`（绝对时刻语义），恰好绕过；旧冒烟每轮 core 存活 <60s，清理循环从未触发。

**诊断手段**：最小复现脚本（本地 origin + spawn core + RPC 轮询 task.list + 订阅通知流），抓到 `缓存保留至 1970-01-02` 与 `缓存清理：删任务` 现场证据。

**修复**（[pf-engine/src/lib.rs](../apps/core/crates/pf-engine/src/lib.rs)）：

```rust
let retain_until = retain_ms(self.cache_policy().retain_days).map(|ms| now + ms);
self.store.mark_finished(task_id, now, retain_until);
```

**附带发现**：`cargo test` 只编测试不产出 bin，`pnpm build` 不含 Rust —— 冒烟前必须 `cargo build --release`，否则用旧二进制跑出「method not found」假象。
