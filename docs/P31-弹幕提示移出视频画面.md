# P31 弹幕提示移出视频画面

用户诉求：**「弹幕配置提示不用放在视频页面上」**。

## 改之前是什么样

`DanmakuLayer.vue` 把四类信息都做成圆角角标，绝对定位叠在视频区左上角（`left/top: 10px`，`z-index: 2`）：

| 角标 | 触发条件 | 文案 |
|---|---|---|
| `.dm-note` | mpv 内核且有弹幕 | libmpv 内核：弹幕由 mpv 以 ASS 字幕渲染 |
| `.dm-badge` | `no_credentials` / `no_match` / 其它错误 | 未配置弹弹play 凭据，仅显示本地弹幕 [配置] / 未匹配… [手动指定] |
| `.dm-badge.hint` | 无错误但 0 条 | 暂无弹幕 [配置弹幕源] |
| `.dm-loading` | 拉取中 | 加载弹幕…（居中） |

问题不只是"不好看"：

- 常驻角标压在片头字幕与画面上，观感像渲染 bug；
- 没配凭据是最常见的初始状态 → **「未配置弹弹play 凭据」会一直挂在画面上**；
- mpv 内核下视频是 Win32 子窗口，会盖住这一层 → 角标要么看不见、要么和画面打架。

顺带发现一个死键：角标上的「配置」走 `window.dispatchEvent(new CustomEvent('pf:open-danmaku-settings'))`，全项目**没有任何监听方**，点了没反应。

## 改成了什么

### 1. 视频画面里只画弹幕本身

`DanmakuLayer.vue` 模板只剩 `canvas` + **用户主动打开**的候选匹配面板（`.dm-picker`）。
四类角标 DOM、`badge` / `showEmptyHint` 计算属性、`onBadgeClick` / `emitSettings` 一并删除。
`.dm-picker` 的 `top` 从 `44px` 回到 `10px`（原来那 34px 是给角标让位）。

### 2. 新增播放页状态行 `.dm-status`

位置：内核控制条（`.engine-row`）**下方**、弹幕发送栏（`.dm-send`）上方 —— 仍在播放卡里，但在视频区之外。

```html
<div v-if="dmStatus" class="dm-status" :class="dmStatus.kind">
  <span class="dm-status-dot"></span>
  <span class="dm-status-text">{{ dmStatus.text }}</span>
  <button v-if="dmStatus.action" class="dm-status-act" @click="onDmStatusAct">…</button>
</div>
```

`dmStatus` 的优先级与文案（`PlayerView.vue`）：

| 优先级 | 条件 | kind | 文案 / 动作 |
|---|---|---|---|
| 1 | `errorKind === 'no_credentials'` | warn | 未配置弹弹play 凭据，仅显示本地弹幕 ·「去配置」 |
| 2 | `errorKind === 'no_match'` | warn | 后端错误文案 ·「手动指定」 |
| 3 | 其它 `errorKind` | err | 后端错误文案 |
| 4 | `loading` | busy | 加载弹幕…（圆点脉冲） |
| 5 | `itemCount === 0` | info | 暂无弹幕（未配置弹弹play 凭据）·「去配置」/ 暂无弹幕 |
| — | 有弹幕且无错 | null | 不渲染，**零占位** |

`onDmStatusAct()`：`picker` → `dmLayer.openPicker()`；`settings` → `store.go('settings')` + `scrollToDanmakuSettings()`。

设置页很长（内核状态 / 播放与缓存 / 片源缓存 / 内容源 / 弹幕…），只切路由的话用户落在页首还得自己找，所以切完直接把 `.content` 滚到 `.dm-settings` 顶部（`scrollTop` 836，区块顶距内容区顶 8px）。两个坑：
- `scrollIntoView` 在这里不可靠，真正滚动的是 `.content`，直接算偏移量；
- 不用 `behavior:'smooth'` —— 它依赖 rAF，窗口不可见时一帧都不推进（Electron 隐藏窗口实测 scrollTop 恒为 0）；瞬时定位也更符合「点了去配置」的预期。

弹幕关闭（`settings.enabled === false`）时整行不出现。

### 3. 为什么没动 `--pf-card-chrome` 预算

状态行出现会多占约 40px（行高 34 + 间隙 6）。实测（高级面板折叠，即常态）：

| 视口 | 播放卡高 | 可视区高 | 余量 |
|---|---|---|---|
| 1440×900 | 647 | 844 | 197 |
| 1366×768 | 612 | 712 | 100 |
| 1280×720 | 576 | 664 | 88 |

最小余量 88px > 40px，因此**不把状态行计入 chrome**：反过来做会让所有窗口的视频白缩 40px。
（若把「手动播放 / 高级」面板展开，卡片会变高并让页面滚动 —— 这是既有行为，与本次改动无关。）

## 仍留在视频区的东西（有意保留）

- 弹幕本体（Canvas 绘制）—— 这就是它的用途；
- `.dm-picker` 候选匹配面板 —— 用户点「弹幕源」才出现，是可关闭的浮层而非常驻提示；
- `.stall-hint` 缓冲提示 —— 只在有播放意图但画面没出来时出现，属于播放状态而非弹幕配置。
