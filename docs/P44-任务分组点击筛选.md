# P44 任务页分组图例可点击筛选

> 需求：顶部分组胶囊（播放中 / 下载中 / 准备中 / 已暂停 / 已完成 / 失败）要能点。
> 点一下只看该组，再点取消；0 条的分组不可点。

## 交互

| 操作 | 行为 |
|---|---|
| 点某个分组胶囊 | 表体只留这一组（含它的分组表头行），chip 高亮，右边出现「显示全部」 |
| 再点同一个 | 取消筛选，回到全部 |
| 点「显示全部」 | 同上（给一个不用回找原 chip 的出口） |
| 0 条的分组 | `disabled`，`title` 写「「已完成」暂无任务」；灰掉，不可选 |
| 任务被删空 | 自动取消筛选（`watch(store.tasks.length)`），不留空表 |
| 筛选后该组被删空 | 表体给一行「「已暂停」分组暂无任务 + 显示全部」 |

筛选只影响**看什么**，不碰调度：被筛掉的暂停任务不会因此恢复下载，
被筛掉的下载任务也不会被暂停（下载槽的判定与视图完全无关）。

## 两个容易被忽略的连带点

**1. 全选必须只选「看得见的」**

`allSelected` / `toggleAll` 从 `sorted`（全部任务）改成 `visibleTasks`（筛后可见）。
否则：筛到 1 个 → 点全选 → 批量删除，会把屏幕外的任务一起删掉，
而用户以为自己只选了 1 个。

**2. 换分组要清掉「看不见的勾选」**

`pruneSelection()` 在 `pickGroup` 里跑：换组后把不在可见集里的勾选丢掉。
不这么做时，`已选 N` 的数字与表格里打勾的行对不上（N 可能大于可见行数），
批量操作的作用范围就成了黑箱。

## 实现要点

- `groupFilter: Ref<TaskGroupKey | ''>`，空串 = 全部。
- `visibleTasks` = `sorted` 按 `taskGroupOf` 过滤（顺序仍是「新建在前」）。
- `visibleGroups` = 筛选时只返回该组（**即使 0 条也返回**，好让表头 + 空态行出现）；
  不筛选时退回 `shownGroups`（空组不占版面）。
- 胶囊从 `<span>` 改成 `<button type="button">`，带 `aria-pressed`；样式补了
  `font: inherit`、`cursor: pointer`、`:disabled { cursor: default }`。
- 选中态用分组色：`border-color: currentColor` +
  `background: color-mix(in srgb, currentColor 14%, var(--panel))`，
  暗色/亮色都跟随 token，不用另写主题覆盖。

## 验证（`.probe/probe44.mjs`，真机 Electron + CDP，PASS 12 项）

先造「播放中 1 + 已暂停 1」两组数据（起播 A → 起播 B 使 A 让位暂停），再验：

- 初始两行可见、无 chip 选中、0 条分组禁用
- 点「已暂停」→ 只剩 1 行 + 只剩该组表头 + chip 高亮 + 出现「显示全部」
- 再点一次 → 两行回来、高亮消失
- 点「播放中」→ 只剩 1 行
- 此时全选 → 只勾中 1 行
- 切到「已暂停」→ 已选变 0（不可见勾选被清）
- 点「显示全部」→ 清筛选，两行回来
