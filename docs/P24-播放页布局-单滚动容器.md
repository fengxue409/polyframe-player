# P24 播放页布局重构：单滚动容器

> 目标：整页只保留 **一个** 纵向滚动容器；播放区、侧栏、内容区不再各自产生滚动条；
> 固定区域内容超出时用「截断 / 折叠」处理；桌面与窄屏共用同一套结构。
>
> **后续修正见 `P25-播放页布局-高度预算修正.md`**：本文 §4 里
> `max-width: (100dvh - 260px) * 16/9 + 34px` 的 260px 预留远小于真实开销（≈323px），
> 导致播放卡比视口还高、sticky 把调试面板标题压在卡片底下切成半行。
> P25 把宽度改为由「视口 - 卡片控制区 - 卡片外开销」反推，并给 mpv 内核单独一档预算。

## 1. 修复前的问题

播放页同时存在 **4 条** 纵向滚动条，滚轮行为取决于指针落点：

| 位置 | 原样式 | 症状 |
|---|---|---|
| 页面内容区 `.content`（App.vue） | `overflow-y: auto` | 基准滚动条（保留了） |
| 右侧信息栏 `.info-side` | `position: sticky; max-height: calc(100vh - 108px); overflow: auto` | 侧栏自己滚，底部「简介/主演」被内层滚动藏住；鼠标移回左边滚轮又变成滚页面 |
| 剧集列表 `.ep-list` | `max-height: 30vh; overflow: auto` | 第三层滚动，窄屏还叠一行 |
| 事件日志 `.log` | `max-height: 300px; overflow: auto` | 第四层滚动，藏在调试面板里 |

外加：切换页面时有/无滚动条会让内容宽度抖动（未设 `scrollbar-gutter`）。

## 2. 新的布局结构

```
.content                       ← 唯一纵向滚动容器（flex:1 / min-height:0 / overflow-y:auto）
└─ .player-view  grid[1fr | 336px]
   ├─ .stage                      左列，align-self: stretch（撑到与右列等高）
   │   ├─ section.card.player         position: sticky; top: 0
   │   └─ section.card.debug          普通流，跟在播放卡后面
   └─ aside.info-side             普通流，无 max-height / 无 overflow
```

窄屏（≤900px）`.stage` 用 `display: contents` 拆平，`.player-view` 切成三行：

```
grid-template-areas: 'player' 'side' 'debug'
```

即 **视频 → 信息栏 → 调试面板**，信息栏仍排在调试面板之前（调试面板是配角）。

## 3. 各区域滚动归属

| 区域 | 是否滚动 | 溢出处理 |
|---|---|---|
| 页面 `.content` | ✅ 唯一滚动条 | — |
| 播放卡 `.card.player` | ❌ | `sticky` 跟随；尺寸按视口封顶 |
| 信息栏 `.info-side` | ❌ | 跟随页面滚动；各分区自身折叠 |
| 剧集 `.ep-list` | ❌ | 只渲染 12 条预览窗口（含当前集），其余「展开全部 N 集」 |
| 事件日志 `.log` | ❌ | 只渲染最新 8 条，「展开全部 N 条」 |
| 简介 `.side-content` | ❌ | `line-clamp: 5` + 展开/收起（原有） |
| 侧栏收起态 `.rail-text` | ❌ | `max-height: 42vh; overflow: hidden` 竖排截断 |
| 调试面板 / 多源监控 | ❌ | 随内容撑高，交给页面滚动 |

折叠状态在换片（标题变化）时自动复位，避免上一部的展开状态带过来。

## 4. 高度约束方式

- **滚动容器**：`.content { flex:1; min-height:0; overflow-y:auto; scrollbar-gutter:stable; overscroll-behavior:contain }`
  - `min-height:0` 让 flex 子项能真正收缩（否则内容撑破容器、页面外再滚一层）；
  - `scrollbar-gutter:stable` 消除切页时的横向抖动；
  - `overscroll-behavior:contain` 阻止滚动链传到 `body`。
- **播放卡**：`position: sticky; top: 0; z-index: 2`，宽度上限
  `max-width: min(100%, calc((100dvh - 260px) * 16 / 9 + 34px))`
  —— 留出顶栏 + 控制区的 260px，保证「视频 + 控制条」整体不超过视口，sticky 顶住时下半截（引擎切换 / 选集 / 倍速）不会被钉在屏外。
- **左列容器** `.stage { align-self: stretch }`：sticky 的包含块是它的 grid 区域，撑满整行后播放卡才能覆盖整段侧栏高度。
- **信息栏**：删除 `max-height` / `overflow`，高度 = 内容高度，直接参与页面向下延伸。
- **矮窗口降级**：`@media (max-height: 620px)` 下播放卡退回 `position: static`（此时整卡接近一屏，sticky 只会裁掉下半截）。常见 1366×768 / 1280×720 窗口（innerHeight 约 640~700）仍保留跟随。

## 5. 为什么需要 `.stage` 这一层

CSS 规定 grid item 的 sticky 包含块 = 它的 **grid 区域**。若播放卡直接占第一行，而侧栏跨两行，第一行的高度就退化成播放卡自身高度 → 包含块等于自身 → sticky 完全失效（实测：滚动时卡片跟着页面走）。

两个解法：让调试面板通栏（行高 = 侧栏）或套一层 stretch 的左列容器。这里选后者，因为通栏会让调试面板在滚动时被播放卡遮住左半边，观感更差。

## 6. 验证

用项目自带 Electron（Chromium 45）加载一份与组件 **逐条对应** 的布局镜像（`.content` / `.stage` / sticky / 页签宽度全部照抄），四个视口分别滚动到 0 / 50% / 100%，实测：

| 视口 | 滚动容器数量 | `body` 可滚 | 播放卡 `position` | 滚动中卡顶 Y | 卡底 Y |
|---|---|---|---|---|---|
| 1440×900 | 1（`.content`） | 否 | sticky | 60 → 60 → 60 | 586（< 视口） |
| 1280×720 | 1 | 否 | sticky | 60 → 60 → 60 | 496 |
| 1024×700 | 1 | 否 | sticky | 60 → 60 → 60 | 352 |
| 420×860 | 1 | 否 | static | 60 → -341 → -741 | 单列：player → side → debug |

- 桌面三档：滚动时卡顶恒为 60（贴住内容区上沿），侧栏 `top` 同步从 60 递减 → **只有侧栏在滚，播放卡钉住**；
- 窄屏：卡随页面正常滚动（`static`），区块顺序为 播放器 → 信息栏 → 调试面板；
- 全尺寸 `body` 均不可滚 → 不存在「外层再冒一条」的情况。

编译产物核对（`apps/desktop/out/renderer/assets/index-*.css`）：

```
.info-side[data-v-…] { width:100%; min-width:0; align-self:start; display:flex; … }   ← 无 max-height / overflow
.card.player[data-v-…] { position: sticky; top: 0; z-index: 2; … }
overflow:auto 出现次数 = 1                                                            ← 即 .content
```

`pnpm --filter @polyframe/desktop build` 与 `typecheck` 均通过。

## 7. 取舍

- 信息栏不再固定：滚到侧栏底部时它随页面上移，但播放卡 sticky 保证画面常驻，这比「侧栏固定 + 内层滚动」更符合看剧场景。
- 展开全部剧集/日志后页面会明显变长——这是刻意的：内容由唯一滚动条承载，而不是再开一个内层滚动区。
- 矮窗口（≤620px 高）放弃 sticky，避免控制条被钉在屏外。
