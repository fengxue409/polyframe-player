# P10 交付总结：第三方视频云解析

**需求**：把截图里那种「选解析接口 → 粘地址 → 解析播放 / 新窗口」的工具做进 PolyFrame。

**结论**：做了，但没做成「一个 iframe 贴几个接口」的壳子，而是**三段式降级 + 可管理接口库**。原因是实测：2026-10 公开流传的 `jx.*` 接口几乎全部关停 —— 截图里的「冰豆解析」（jx.xmflv.com）现在返回的是「江湖路远，后会无期」公告页，aidouer 同模板，m1907 被 Cloudflare 挡。**只做 iframe 的话，这个功能在交付当天就是三个死链。**

---

## 1. 三段式降级

| 段 | 条件 | 结果 |
|---|---|---|
| ① 直链 | 接口回 JSON，或 HTML 里内嵌 m3u8/mp4 | 进任务 + 本地代理：边下边播、缓存三档、libmpv、断点续传全部复用 |
| ② 嗅探 | 接口只给播放页，正片地址由页面 JS 运行时换取 | 主进程隐藏窗口实跑 JS，`webRequest` 截 m3u8 → 同样进代理 |
| ③ 内嵌 | 嗅探也拿不到（登录/点播/验证码） | iframe 嵌播放页；禁止内嵌时改用独立窗口 |

第二段是这次的技术核心。**用 curl 抓页面拿不到正片**——播放页的直链是 JS 现场向自家后端换的，所以必须真的把页面跑起来。实现：`BrowserWindow({show:false})` + 独立内存分区 + 静音 + `backgroundThrottling:false` + `autoplayPolicy:no-user-gesture-required`，三路并行取证：

1. `session.webRequest.onBeforeRequest` 抓 `.m3u8/.mp4/.flv/.mpd`（刻意不抓 `.ts` 分片，否则几百条噪声）；
2. 每 700ms 轮询 `video.currentSrc`（直嵌 mp4 的页面不发 XHR）；
3. 每 1.8s 尝试点 `.vjs-big-play-button` / `.dplayer-play-icon` / `video`（部分页面必须点一下才拉流）。

命中 m3u8 立即返回，否则等超时取已有候选。

## 2. 接口是「库」，不是常量

`parse_services` 表（与 `catalog_sources` 同构）：`direct://` 是内置哨兵 = **零接口直连嗅探**，不依赖任何第三方、长期有效；其余 6 条公开接口如实显示测活状态（可用 / 失效 / 未测），支持新增、改名、停用、删除、批量导入、恢复预设。测活会区分「域名已死」「已关停（响应含关停特征串）」「服务在线但首页 404」，不笼统报错。

## 3. 看不见的坑

- **二次编码**：不少接口把整条 URL `encodeURIComponent` 后再塞进 JSON，`%3A%2F%2F`、`%2F` 都要还原，只做 `\/` 反转义会得到 `https://host%2Fpath`。
- **假候选**：HTML 里 `'ep.m3u8'` 这种片段会被相对路径归一成不存在的地址，所以候选要按 m3u8 优先排序并允许用户手动换（结果区有候选列表 + 逐条「播放」）。
- **hls.js 的 src 是 `blob:`**：E2E 断言不能找 `/m3u8/`，否则误判失败（第一版就踩了）。
- **首屏下拉为空**：内核比界面晚就绪，`onMounted` 里判 `online` 会永久跳过加载 —— 必须 `watch(online)`（E2E 抓出来的真 bug）。
- **IPC 错误前缀**：`Error invoking remote method 'pf:rpc': Error: ...` 会直接显示在错误卡片上，已在 store 层剥离。

## 5. 边界与后续

- 解析能力取决于第三方接口与站点本身；我们不内置任何解密逻辑，只做「把地址换成能播的流」和「说清楚为什么换不到」。
- 接口内容由第三方提供，合规使用需自行确认。
- 若要长期稳定，建议用户自建解析服务并填入接口库（模板支持 `?url=` 与 `{url}` 两种写法）。
- 未做：弹幕、清晰度/线路切换（接口页自带）、解析服务的批量测活并发（目前串行，避免同批 CDN 风控）。
