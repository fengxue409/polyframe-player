# P29 预缓存作为默认播放策略

日期：2026-10-31
范围：`packages/shared`、`apps/desktop`（player store / 设置页 / 播放页）、`apps/core`（pf-engine / pf-core）

## 1. 改了什么

`CacheMode` 的默认值由 `stream`（边下边播，只调度播放头窗口）改为 `precache`（预缓存，播放头之外低优持续拉完剩余分片）。

三档语义未变，`task.create` / `task.set_cache_mode` 的参数与返回结构未变，只是「没指定时用哪一档」变了。

默认值现在只有一个出处：

| 层 | 位置 | 说明 |
|---|---|---|
| TS | `packages/shared` `DEFAULT_CACHE_MODE = 'precache'` | 前端初值 + 迁移目标 |
| TS | `LEGACY_DEFAULT_CACHE_MODE = 'stream'` | 迁移判据（旧默认） |
| Rust | `impl Default for CacheMode → Precache` | 内核唯一兜底 |
| Rust | `pf-core` `task.create` / `netdisk.play` 的 `unwrap_or_default()` | 缺省 + 非法值都落到这里 |
| SQL | `tasks.cache_mode TEXT NOT NULL DEFAULT 'precache'` | 新库 |

## 2. 涉及哪些播放路径（逐条）

判定原则：**本次播放是否要新建任务**。新建 → 用默认档；复用 → 见下。

### 2.1 启动

| 路径 | 行为 |
|---|---|
| 首页/发现页点卡片 → `catalog.playFromQueue` → `playEpisode` → `task.create` | 新建任务，带 `newTaskCacheMode`（默认 precache） |
| 播放页手输 URL / 镜像 → `player.createTask` | 同上 |
| 直链起播 `playDirect` | 同上 |
| 网盘 `netdisk.play` | 前端传 `newTaskCacheMode`，内核缺省也是 precache |
| 内核启动 `restore_from_db`（未完结任务续传、媒体库任务重建） | **不新建任务**，按库里 `cache_mode` 原样恢复；库值非法才回落默认 |

### 2.2 切换

| 路径 | 行为 |
|---|---|
| 换集（`playAt`）、换线路（`switchPlaySource`） | 新 URL → 新任务 → 默认档 |
| 换内核 `switchEngine`（hls ↔ mpv） | 不重建任务，档位不变（与播放内核无关） |
| 任务页单任务切档 `task.set_cache_mode` | 立刻生效，并给任务打 `cache_mode_explicit=1`（见 2.4） |
| 同集重播 / 播完重看（URL 相同 → 内核 `find_task_id_by_url` 复用） | **按本次请求的档位**（前端每次都传当前默认档），任务 id 不变、已下载分片继续复用 |

### 2.3 恢复

| 路径 | 行为 |
|---|---|
| 播放历史/收藏点「继续观看」→ `playEpisode` | 若该 URL 的任务还在 → 走复用分支（档位按本次默认）；任务已被 TTL/容量清理掉 → 新建，默认档 |
| 内核重启后 `task.list` / 媒体库 | 档位来自库，与关闭前一致 |
| 续播 seek（`catalog.pendingSeek`）、倍速恢复、弹幕 | 与档位无关，未改动 |

### 2.4 「用户显式选择」的边界

复用任务时不能无脑套默认档，否则任务页单任务设置形同虚设。为此新增库内标记：

- `task.set_cache_mode`（任务页/调试面板切换）→ `cache_mode_explicit = 1`；
- `task.create` 复用时：`explicit = 1` → 用库里的档，请求值不生效；`explicit = 0` → 用请求值，并随 `upsert` 写回库。

顺带修掉一个分叉：`upsert_task` 的 `ON CONFLICT DO UPDATE` 之前不更新 `cache_mode`，导致「内存里是新档、库里是旧档」，重启后档位静默回退。现在两边一致。

## 3. 一次性迁移

### 3.1 前端 localStorage

旧版每次改倍速都会 `saveUiPrefs()`，把当时的默认档（`stream`）写进 `pf.newTaskCacheMode` —— 那是默认值，不是用户选择。所以：

- 新增 `pf.newTaskCacheModeUser = '1'`，只在用户从设置页/播放页改「播放默认档」时写入（`saveCacheModePref()`）；
- `init()` 迁移：值等于旧默认 `stream` **且** 无用户标记 → 升级为 `precache`；值为 `online`/`precache` 的一律保留（旧默认写不出这两个值，只能是用户改的）。
- 代价：升级前**显式选过 stream** 的用户会被迁移成 precache 一次，改回来即可（改完就有标记，不会再被迁移）。

### 3.2 老库任务

不批量改库。老任务（`cache_mode='stream'`、`explicit=0`）在下次被播放（复用）时自然升级为默认档；`explicit=1` 的（用户改过）永久保留。

## 4. 副作用与约束（需要知情）

- **带宽/磁盘**：precache 会把整片拉完。默认容量上限 20GB、播完 TTL 1 天（`cache.policy`），大码率剧集会更快触发容量 LRU 淘汰。
- **直播**：`live && precache` 在 `in_schedule_window` 里退化为 stream 窗口，不会无限追流。
- **在线档**：`online` 仍是「不落盘」；`never precache` 的判断只在任务自身档位上，不受默认值影响。
- **导出** `task.export`：不变，仍按已缓存分片 concat。
- 设置页文案改为说明影响的路径与代价，选项标注「预缓存（默认）」。

内核端到端的关键证据：

- 未传 / 传非法 `cacheMode` → `precache`；显式 `stream` 仍生效；
- 30 片任务：`stream` 无播放头只下 **15/30**（窗口 0..14），`precache` 下 **30/30**（全量）；
- 复用未显式设置的任务 → 档位切到 `precache` 并从 15 补到 30（断点续存、任务 id 不变）；
- `task.set_cache_mode(stream)` 后复用并显式请求 `precache` → 仍是 `stream`（用户显式优先）；
- 重启内核：`precache` / 显式 `stream` 两个任务档位都不丢；重启后再复用未显式任务 → 仍是 `precache`。

界面验收（真渲染产物）：

- 设置页「新建任务默认模式」默认选中「预缓存（默认）」，说明文案完整可读（`.cachecheck/ui/01-settings.png`）；
- 播放页「手动播放 / 高级」面板默认档 = `precache`；
- 点「播放」后真实发出的 `task.create` 参数含 `cacheMode: "precache"`（同一次运行还观察到 `catalog.history.record` 正常打点）。

## 6. 已知边界

- 迁移只在 `player.init()` 跑一次；若用户手工清掉 localStorage 的 `pf.newTaskCacheModeUser`，会再迁移一次（值若为 `stream`）。
- `catalog.playEpisode` 与各起播入口都读 `player.newTaskCacheMode`，没有第二处硬编码；新增起播入口必须同样传 `cacheMode`，否则内核会落到缺省（也是 precache，但会绕过用户的显式选择）。
- 剧集级预缓存队列（`series`）沿用任务自身档位，不因默认值变更自动改变已有队列。
