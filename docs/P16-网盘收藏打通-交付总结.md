# P16 交付总结：网盘 × 收藏体系打通

> 批次日期：2026-10-27 · 前置：P9b（网盘视频源插件）、P7（收藏/片源聚合）、P9（连播/继续观看）、P11/P13（追更巡检）

## 1. 这一批解决什么

P9b 交付后，网盘文件只能「即时播放 / 加任务」，与影视体系的收藏、连播、进度、继续观看、追更完全割裂——看一半的网盘剧集关掉应用就找不回来。本批把网盘内容并入既有收藏管线，**不新增任何播放器/媒体库分支**：

| 能力 | 之前 | 现在 |
|---|---|---|
| 网盘剧集目录 | 只能进目录逐个点播 | 一键收藏为剧集，集列表自动生成，支持连播 |
| 看一半退出 | 无记录 | 继续观看行（带集名 + 百分比） |
| 多账号同名内容 | 各自独立 | 归并同一条收藏的不同片源（含与 CMS 站同名归并） |
| 目录新增集 | 需手动进目录翻 | 追更巡检自动检出并提示 `+N 集` |

## 2. 设计核心：稳定 shim URL 作为剧集快照

收藏的剧集快照里存的是 `http://127.0.0.1:{proxyPort}/nd/{nd_token}/{owner}/{fileId}/v.mp4`：

- `nd_token` 落 `settings` 表、跨重启稳定（P9b 设计）→ 快照 URL 长期有效；
- 直链过期由 proxy 的 401/403/410 强制换链兜底（P9b 设计）→ 快照永不需要刷新；
- `.mp4` 结尾 → 引擎判 MP4 直链 → 分块/缓存/Range 全套既有管线。

因此**进度上报、续播 seek、连播队列对「网盘 URL」与「CMS URL」完全无感**，catalog 侧零改动。

### RPC 契约

```
netdisk.favorite.add
params: { accountId?|shareId?, fileId?|dirId?（二选一）, name }
result: { favorite: Favorite }
```

- 片源引用：`api = "netdisk:{owner}:{dirId|fileId}"`、`vod_id = dirId|fileId`、`origin = "netdisk"`
- 收藏元数据：`type_name = "网盘"`、`remarks = "{provider名}·{账号名/分享标题}"`
- 错误：目录无视频文件 / 目标不可播 / 读目录失败，均回可读消息

## 4. 追更机制

`favorite.refresh` 与后台巡检（P11/P13）共用 `refresh_favorite_sources`，网盘片源分流：

1. Job 收集时按 `api` 前缀分流：`netdisk:` 进网盘队列，其余走 CMS `detail_one`；
2. 网盘 Job：`split_owner_ids` 还原 account/share → `refresh_netdisk_episodes` 重新列目录（翻页 cap 20 页）→ 与旧快照集数对比；
3. 集数有增才 `update_favorite_source_episodes`（remarks 保留原值）——与 CMS 口径一致（只增不删，避免网盘抖动误清快照）。

## 5. 冒烟验证（smoke-p16.mjs，23/23）

- **A 目录收藏**：3 视频 + 1 非视频 → 3 集、集名去扩展名、shim URL 形态正则校验、`type_name=网盘`、remarks 含 provider 与账号名
- **B 幂等 + 归并**：重复收藏同目录 → 仍 1 条源；账号 B 收藏同名目录 → 归并同一条收藏、2 条源
- **C 单文件收藏**：`流浪地球2.mp4` → 名字去扩展、1 集；不存在的目录被拒绝
- **D 进度打通**：`progress.set` 挂网盘收藏 → `progress.list` 可见（继续观看数据源）
- **E 追更**：假网关目录加第 4 集 → refresh 检出 `added=1`、快照回写 4 集；再 refresh 无新增不报
- **F 清理**：删收藏联动清进度、删账号

冒烟用**独立数据目录**（临时 `LOCALAPPDATA`，运行后删除）——曾因共享数据目录的残留账号污染断言（旧 source 混入导致计数全错），修复后稳定。

## 6. 调试插曲（对后续有价值）

「`method not found: netdisk.favorite`」曾连续误导排查方向：

1. 先怀疑**编译产物陈旧**——`strings` 验证二进制是假信号（`strings` 命令不存在返回空 + release 下 match &str 被优化成跳转表、方法名完整字符串不在二进制里；应探针**错误消息中文字面量**才是有效信号）；
2. 再怀疑**增量编译缓存损坏**（clean + rebuild 依旧）；
3. 最后给 handle 入口加 `eprintln!` 才看到 `rest="favorite"` —— **方法名层级错位**：main.rs 已剥 `netdisk.` 前缀，handle 内 arm 是 `favorite.add`，完整方法名应为 `netdisk.favorite.add`。

教训：**新增 RPC 方法名 = 模块前缀 + handle 内 arm 名**，加方法时先对齐同文件既有命名（`account.list`/`share.add`）；二进制探针用业务字符串而非 match 模式字符串。
