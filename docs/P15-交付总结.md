# P15 交付总结：倍速播放 + 源站健康巡检一键停用

日期：2026-10-27。本批为**纯前端批次**（Rust 内核零改动），补齐两个体验空白。

## 1. 倍速播放（hls + mpv 双内核）

### 现状问题
播放器此前完全没有倍速能力（代码里无一处 `playbackRate`），长剧连播场景下是硬伤。

### 实现
- **状态与记忆**：`player.playbackRate`（0.25–4），localStorage `pf.playbackRate` 持久化，`init()` 时恢复，`saveUiPrefs()` 落盘。
- **hls 内核**：PlayerView watch `[playbackRate, engine]` 写 `video.playbackRate`；`onCanplay` 兜底补写（`src` 变化会重置 playbackRate）。Chromium 默认 `preservesPitch`，变速不变调。
- **mpv 内核**：`setPlaybackRate` 经 `mpv.set` 写 `speed` 属性；`playMpv()` 在 `MpvLoad` 后补一次——新 attach 的 mpv 实例 speed 归 1，不补则重连/切核后倍速丢失。
- **UI**：控制条倍速下拉（0.5x / 0.75x / 1x / 1.25x / 1.5x / 2x / 2.5x / 3x），1.0 显示「倍速」占位文案；对极端值 try/catch 容错（个别容器拒绝超范围倍速）。

## 2. 源站健康巡检 + 一键停用失效站

### 背景与设计取舍
GYING 调研中「域名容灾」产品原则的落地：采集站死亡率高，失效站留着只会拖慢聚合搜索（每次搜索/分类都要等它们超时）。

**关键发现**：后端 `catalog.source.probe_all` 的 `results` 早已返回每条的 `id`——无需新增后端 RPC，纯前端即可实现精准停用（比最初设想的 `source.health` 新 RPC 少一个面）。

### 实现
- `probeAllSources()` 扩展：记录失效站 `deadIds`（**只含当前启用中的**，已停用的不再打扰）与 `deadNames`，测速完刷新列表。
- `disableDeadSources()`：逐个 `catalog.source.update { enabled: false }`，单个失败不阻断；**只停用不删除**，便于复查恢复。
- `dismissDead()`：忽略本次结果。
- **UI**（源站管理面板顶部警示条）：`巡检发现 M 个失效源站（名称…），留着会拖慢聚合搜索` + 「一键停用」「忽略」；动作完成后 toast 报数。
