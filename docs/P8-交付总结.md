# P8 交付总结：全网视频源集成（2026-10-26）

> 需求：全网搜集视频源，并集成到工具里。
> 落地形态：**内置实测预设库（18 站）+ 任意公开源清单批量导入 + 全量测速**，把「逐个手填 API」变成「一次同步/粘贴/订阅即可」。

## 1. 做了什么

| 能力 | 入口 | 说明 |
|---|---|---|
| 预设库 | 发现页「源站」→ **同步预设库** | 18 个实测可用 CMS 采集站；新装自动播种，老用户补齐缺口（同 API 不重复、不改用户改名） |
| 批量导入 | 同上 → **批量导入** | 粘贴文本或填订阅 URL；解析后逐条探测，只入库能返回数据的站 |
| 全量测速 | 同上 → **全部测速** | 12 路并发，成功回写延迟与最近成功时间，失败站名单回显 |
| 导入格式 | — | 纯文本 `名称$URL` / 订阅 JSON（LibreTV `sources[]`、MoonTV `api_site{}`、根数组）/ Base58(JSON) 订阅 |
| 安全边界 | — | 清单标注 `isAdult` 的条目一律丢弃；直播源（`liveSources`/`.m3u`）不入采集站体系 |
| 设置页 | 设置 → 发现源站 | 同步预设库 / 全部测速 两个快捷按钮 + 预设覆盖率文案 |

## 2. 源站清单怎么来的（可复现）

1. **公开渠道汇总**：mac-cms 采集站接口一览（19 条）+ MoonTV/LunaTV 公共配置仓库（jin18 / jingjian 两份，共 ~88 条，去重后 59 条候选）。
2. **第一道实测**：`?ac=list&pg=1` 返回 JSON 且 `list` 非空 → 42/59 通过。
3. **第二道实测（关键）**：`?ac=detail&wd=庆余年` 真能搜到片且 `vod_play_url` 带 m3u8 → 剔除「只列表可搜不可查」「接口禁关键词搜索」的站。
4. **剔除成人向**：清单里带 `🔞`/`isAdult` 的 14 个站点全部不入库。
5. **剔除环境不通**：飘零资源（curl 通、rustls 握手被拒）、卧龙/天涯/索尼（域名出售 / 禁搜索 / CF 拦截）、豆瓣与茅台（API 禁关键词）。
6. **最终 18 站**，release 内核真机复测 **18/18 全部可用**（281ms ~ 1285ms）。

## 3. 协议与实现

### 新增 RPC（camelCase，与 packages/shared 同构）

```
catalog.source.presets                 → { version, total, installed, presets[{name,api,installed}] }
catalog.source.import {text?,url?,probe?,enabled?,builtin?}
                                       → { imported[], importedCount, skipped, failed[], failedCount, adultDropped }
catalog.source.probe_all {ids?}        → { ok, fail, results[{id,name,api,ok,latencyMs,samples,error}] }
```

导入流程：解析 → 归一（去尾 `/`、http(s)、主机含 `.`）→ 按 api 去重 → 与库内已有比对（skipped）→ 12 路并发探测 → 只写成功项（顺便回写延迟）。

### 代码落点

- `pf-parser::sourcelist`（新增）：`parse_sources` 三形态归一 + 自带 Base58 解码 + 5 组单测
- `pf-core::presets`（新增）：`PRESET_VERSION=2` + 18 条 `(名称, API)`，文件头写明维护约定与已知剔除原因
- `pf-core::catalog`：三个 handler + `fetch_subscription`（15s/1MB 上限）+ `insert_imported`
- `pf-parser::cms`：外层 `code/page/pagecount/total` 弹性数字、`list` 弹性数组（**实测暴露的真 bug，见 §4**）
- `stores/catalog.ts`：`loadPresetStat` / `syncPresets` / `importSources` / `probeAllSources`，均按 12 条分批
- `DiscoverView` / `SettingsView`：工具条 + 导入区 + 计数
- `electron/main`：`import` / `probe_all` RPC 超时放宽到 60s

## 4. 实测暴露并修掉的 bug

| bug | 现象 | 根因 | 修复 |
|---|---|---|---|
| 14/19 预设站被误判失败 | 真机 `probe_all` 只成功 4 个 | 大量采集站把 `page/total/code` 回成字符串 `"1"`，`u32` 反序列化直接失败，整站判错 | cms 外层改弹性数字解析；`list` 同时容忍 null/非数组/坏条目 |
| engine 单测偶发失败 | `attempt to write a readonly database` | 两个用例共用 `pid` 命名的临时库目录，并行时互相 `remove_dir_all` | 临时库路径加自增序号 |
| P7 冒烟断言写死 5 源 | 回归 2 项失败 | 预设从 5 扩到 18 | 改为「≥5 且全 builtin」与「基线+1」 |

## 6. 使用说明

1. **老用户补齐**：发现页 → 源站 → 同步预设库（只补缺，不动你已有的源与启停状态）
2. **加自己的源**：批量导入里粘贴 `名称$https://…/api.php/provide/vod`（一行一个），或填别人分享的订阅 URL
3. **定期体检**：全部测速 → 延迟高/失败的站手动停用；搜索结果的「失败源站」提示也能反推坏站
4. **注意**：采集站域名更换频繁，预设只是「今天实测可用」的起点；源内容由第三方站点提供，请自行确认合规使用。

## 7. 后续方向（未排期）
