# P50 · 应用内版本检查与自动升级 — 交付总结

日期：2026-11-07

## 需求回顾

- 启动时 + 定期向服务器检查新版本；发现新版后自动下载升级包；一键完成升级替换。
- 同时兼容 **免安装（便携）版** 与 **安装版**，分别处理升级方式。
- 升级保留用户数据与配置；处理下载失败、断点续传、版本回退。
- GitHub 直连不稳，准备多个代理通道自动降级。

## 方案：自研 updater（不用 electron-updater）

electron-updater 对 portable 形态支持差、代理通道不可控，故自研 `electron/main/updater.ts`（约 700 行）。

### 更新源与代理通道

- 源 = GitHub Releases（`api.github.com/repos/{repo}/releases/latest` + 资产下载）。
- **通道列表**：`direct` → 内置 4 个镜像前缀（`gh-proxy.com` / `ghfast.top` / `ghproxy.net` / `gh.llkk.cc`）→ 用户自定义前缀。前缀拼法：`<proxy>/https://github.com/...`。
- 逐通道降级，**成功的通道 id 记入配置**（`lastGoodChannel`），下次优先使用；设置页可一键「测试通道」看各通道延迟/可用性。
- 更新源仓库可配置：设置页输入框（`owner/repo`）或环境变量 `PF_UPDATE_REPO`；默认占位 `polyframe-player/polyframe-player`，**发布方需要改成真实仓库**。

### 检查与下载

- 启动 10s 后首查，此后按配置间隔（1/3/6/12/24/72h，默认 6h）定期查；开发模式不自动查。
- 发现新版且开了「自动下载」（默认开）即自动下载；下载用 **HTTP Range 断点续传**：`.part` 半成品留在 `%LOCALAPPDATA%/PolyFrame/updates/`，失败重试从断点继续；服务器不支持 206 时自动从头下。
- **空闲超时 45s**（AbortController 逐块重置，不是总时长超时），单次下载最多 5 轮断点重试；进度 400ms 节流推送渲染层。
- **SHA256 校验**：Release 里放 `<安装包名>.sha256` 资产即强校验，不匹配删包报错；没有该资产则跳过（UI 标注未校验）。

### 双形态升级

| 形态 | 升级方式 |
| --- | --- |
| 安装版（nsis） | 下载 `*Setup*.exe` → 写 `apply-update.cmd`（chcp 65001）：等本进程退出（最多 90s）→ `/S` 静默安装（NSIS 沿用注册表记忆的安装目录）→ 自动拉起新版 |
| 便携版（portable） | 下载非 Setup 的 `*.exe` → 复制到 exe 同目录 → 利用 Windows「运行中 exe 仍可 rename」特性：当前 exe → `*.pfold`，新 exe 顶到原位 → 拉起新版后 `app.exit(0)`。任一步失败回滚改名并报错 |

### 用户数据保留

- 用户数据（内核数据、缓存、日志）在 `%LOCALAPPDATA%/PolyFrame`，UI 偏好在 `userData`，都与安装目录/exe 本体分离，升级天然不覆盖。
- **回退**：
  - 「历史版本」列表（最近 10 个 Release）→ 任意旧版「下载并安装」（同一套下载/校验/安装流程）。
  - 便携版额外保留一代 `*.pfold` 备份：新版存活一个会话后自动清理；也可在设置页「还原上一版」一键回滚。
- 下载失败：错误进状态机 + UI 显示，断点保留可重试；SHA 不匹配自动删包防半包升级。

## IPC 与 UI

- 主进程：`pf:update-state/check/download/install/config/history/install-version/test-channels/restore-backup/open-dir`；状态经 `pf:update-state` 推送。
- preload：`window.polyframe.update*` 系列暴露（仅顶层 frame，沿用 H1 守卫）。
- 渲染层：`stores/update.ts` pinia store；设置页新增「软件更新」卡片（版本/形态、阶段状态、进度条、一键升级、自动检查与间隔、更新源、通道探测表、历史版本回退、还原上一版）；SideNav「设置」入口在有新版时挂红点；「关于」卡片版本号改为动态。

## 验证

- `pnpm --filter @polyframe/desktop typecheck` ✅
- `pnpm --filter @polyframe/desktop build` ✅
- `node ui-snapshot.mjs 1440x900` ✅：设置页新卡片渲染正常、无横向溢出、无新增 renderer 报错（home slides 溢出与 ResizeObserver 提示为既有问题）。

## 已知限制

1. 默认 `repo` 是占位值，发布方需在设置页改或设 `PF_UPDATE_REPO`；Release 资产需同时上传 `.exe`（命名含 `Setup` 区分安装版/便携版，与 electron-builder 现有产物命名一致），可选附 `.sha256`。
2. 安装版静默安装依赖 NSIS 注册表记忆安装目录；未走安装器手拷的目录（伪安装版）会装回默认目录。
3. SHA256 校验依赖发布方上传 `.sha256` 资产，未上传时只做文件大小比对。
4. 打包（`pnpm dist`）前按惯例先 bump 版本号（当前 0.1.1），本批未改版本。
