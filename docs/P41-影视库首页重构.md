# P41 · 影视库首页重构——信息层级与首屏预算

> 需求：**优化影视库首页布局，更符合当下主流审美；重排信息层级，合理布局海报/分类/推荐；
> 统一配色、间距、字体；保证浏览、搜索、切分类、进详情都顺手；适配常见屏幕尺寸。**
>
> 原则：只改 `HomeView.vue`（模板 + 样式 + 少量交互状态），不动数据层与内核；
> 全部颜色走 App.vue 的设计 token，亮色皮肤自动跟随。

## 1. 结论先行

旧版首页的问题不是「不够花」，而是**首屏被自己吃掉**：页头 + 搜索 + 类型条 + 推荐位
在 1440×900 上占掉 **561px**，第一张海报才刚露头，等于「打开就是三行工具 + 一屏海报的 1/4」。

重构后同一断点第一张海报上移到 **445px**，第二行海报露出 85%（可点、可见、提示还能往下滚）。

| 指标 | 重构前 | 重构后 |
|---|---|---|
| 首张海报 top（1440×900） | 561px | **445px** |
| 第二行露出比例 | 25% | **85%** |
| 工具条行数（1440） | 2（搜索 / 类型） | **1** |
| 类型胶囊 vs 筛选按钮 | 各占一行（窄屏） | **同行**（≤480 也同行） |
| 海报比例 | 16:9 横版 | **2:3 竖版**（源站 cover 就是竖版） |

## 2. 最终页面结构

```
section.home-view
├─ header.home-head        影视库 + 数据来源徽章 + [片库|收藏] + 刷新
├─ div.toolbar             搜索(520px 上限) · 类型胶囊(全部/电影/剧集/动漫/综艺) · 筛选
│   └─ div.filter-panel    默认收起；展开后每个维度一行，行内单选、行间「与」
├─ div.active-filters      已选条件回显（chip 可单删 / 清空全部）
├─ div.hero                推荐位（条件显示，见 §5）
├─ section.row-block       继续观看（横向行，2:3 小卡 + 进度条 + 剩余时长）
├─ div.sec-head            「全部影片 N 部」+ 排序 [热门|豆瓣评分|播放量|最新更新]
├─ div.poster-grid         2:3 海报流（auto-fill，卡片含评分/画质/热度角标）
└─ div.empty / .boot-alert 空态 / 起播失败原地重试
```

层级原则：**能用一个动作完成的不要拆成两个**（搜索和分类同排）、
**次要信息降级不删除**（高级筛选收进按钮并带计数徽章）、
**同一屏只讲一件事**（推荐位、继续观看、结果列表三段互斥压缩，见 §5）。

## 3. 视觉规范（只准用 token）

| 维度 | 取值 | 说明 |
|---|---|---|
| 页头标题 | `--fs-xl` / 700 | 与侧栏一级标题同级，不做超大 hero title |
| 正文/卡片标题 | `--fs-sm` / `--fs-xs` | 卡片标题 2 行截断且 `min-height: 2.84em`，保证网格基线齐平 |
| 段落间距 | `--sp-2/3/4/5` | 页头 12、工具条 12、推荐位 16、区块 24 |
| 圆角 | `--r-md`(控件) / `--r-lg`(海报) / `--r-xl`(推荐位) | 控件小圆角、媒体大圆角，两级就够 |
| 强调色 | `--accent` / `--accent-hi` / `--accent-soft` | 选中 chip、主按钮、进度条统一用它 |
| 海报宽 | `--poster-min: 152px`（≤1180: 140 / ≤900: 124 / ≤720: 96） | 只改这一个变量就能整体缩放网格 |

**禁止写死随底色变化的颜色**（P34 教训）：海报角标允许固定深底白字（压在图上，与皮肤无关），
其余一律 `--panel/--line/--text-*`。

## 5. 三条互斥 / 让位规则

1. **推荐位（hero）条件**：片库视图 + 无筛选 + 无搜索 + `innerHeight ≥ 820` + **窄屏有继续观看时让位**。
   矮窗口下宁可不显示，也不把片库挤到第二屏。
2. **继续观看**：只要历史里有「看了一半」的记录就显示，**不再按屏高砍**——它是用户自己的进度，
   属于内容而不是装饰（矮窗口/手机上更需要一键续播）。
3. **两者只能留一个**（仅窄屏）：`narrow && continueItems.length > 0 → 隐藏推荐位`。
   手机一屏放不下「编辑推荐 + 我的进度 + 片库」，按「我的 > 编辑的」排序取舍。

## 6. 踩过的坑（改这块前先读）

**① `flex-wrap` 先按 `flex-basis` 断行，再收缩。**
把「筛选」按钮从独立一行挪回类型条同一行时，先把 `.qb-types` 设成 `flex: 1 1 auto` 无效——
basis:auto 时父容器先判定「放不下」直接换行，收缩根本没发生。窄屏要用 **`flex: 1 1 0`**（basis 0），
宽度不够时才会真正走「收缩 + 横向滚动」。

**② 胶囊别乱撑满。** `flex: 1 1 0` 在 820px 下会让类型胶囊被拉成 690px、右半截是空白，
比「筛选单独一行」更难看。所以只在 **≤480px（类型必然溢出）** 用 `flex: 1 1 0`，
480–900 用内容宽度（胶囊内容比可用宽度小，撑满只会留白）。

**③ 两个强调色实心控件相邻会被读成一个蓝块。** 搜索按钮和「全部」都是 `--accent` 实心，
默认 8px 间距下截图看起来是一整条。给 `.qb-types` 加 `margin-left: 6px`（合计 14px）才分得开。

**④ 横向行别留原生气泡滚动条。** `.row-track` 原来 `scrollbar-width: thin` + `padding-bottom: 4px`，
在亮色皮肤下横在卡片文字下面很难看。改成 `scrollbar-width: none` + `::-webkit-scrollbar{height:0}`，
靠「最后一张卡被切一半」当可滑提示。

**⑤ 卡片基线对齐靠 `min-height` 而不是 `align-items`。** 标题 1 行/2 行混排时，
网格里同一行的副标题会跳；`.p-title` 固定 `min-height: 2.84em` + `line-clamp: 2` 解决。

**⑥ 首屏预算要按「实测 top」调，不要按感觉。** 用 `.probe/measure-home2.mjs` 量
`grid.top / 卡片尺寸 / 完整行数`，改完立刻复测；`29vh` 的推荐位在 900px 高下就是 261px，占得太狠，
降到 `23vh`（207px）才把第二行海报让出来。

## 7. 验证

```bash
pnpm --filter @polyframe/desktop typecheck     # 通过
pnpm --filter @polyframe/desktop build         # 通过
node ui-snapshot.mjs 1440x900                  # 暗色，落 .screenshots/ui/1440x900/home.png
PF_THEME=light node ui-snapshot.mjs 1440x900   # 亮色，落 ...-light/
node ui-snapshot.mjs 820x620 / 420x860
node .probe/measure-home2.mjs                  # 断点体检（列数/溢出/首屏行数）
node .probe/probe-home-func.mjs                # 交互回归 10/10
node .probe/probe-continue.mjs                 # 继续观看行（注入假历史后截图）
```

`probe-home-func.mjs` 覆盖：初始态 → 切类型（标题/选中态/推荐位让位）→ 切排序 →
展开高级筛选 → 选地区生成已选条 → 搜索 → 一键清空回到初始态 → 无横向溢出。**10/10 通过。**

## 8. 已知边界

- 亮色皮肤下推荐位仍是深色块（内容封面类元素刻意不跟随主题，同 P34 的「视频区/封面叠加层」约定）。
- 404px 以下结果栏会折成两行（「全部影片 N 部」+ 排序右对齐），属可接受降级。
- 推荐位需要 `innerHeight ≥ 820`，1280×800 的笔记本屏看不到它——这是有意的内容优先取舍。
- 首页是保活页：历史只在首次挂载 + `playSeq` 变化（1.2s 合并窗口）时刷新。
