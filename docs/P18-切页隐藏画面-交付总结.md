# P18 切页隐藏画面：离开播放页收起 mpv 视频表面，播放不停（交付总结）

> 需求原话：「切页时隐藏画面、播放继续」。
> 交付日期：2026-10-28

## 1. 症状与真因

播放页在 `App.vue` 里是 `v-show` 保活的（`<PlayerView v-show="store.route === 'player'" />`）—— 设计目的是切页不打断播放、`<video>`/弹幕元素常驻。

问题只出在 **libmpv 内核**：视频表面不是 DOM，而是 Rust 侧 `CreateWindowExW(WS_CHILD)` 创建、`SetParent` 到主窗口 HWND 的原生子窗口。子窗口恒绘制在父客户区之上，**完全不吃 DOM 的 `display:none`**。

过去的隐式行为是：

1. 切页 → PlayerView 根节点 `display:none` → `video-wrap` 的 `getBoundingClientRect()` 全 0；
2. `ResizeObserver` 触发 `syncMpvRect()`，把 `{0,0,0,0}` 交给 `mpv.move`；
3. `pf-mpv::window::move_window` 对宽高做了 `w.max(1)` 保护 → 子窗口被压成 **1×1 像素**钉在客户区左上角；
4. 回到播放页时，靠 RO 再次回调把矩形写回来 —— 这条链一旦错过一拍（debounce 60ms、RO 在 `display` 翻转时的投递时机、切回时布局未落定），矩形就**永远停在 0**，画面再也回不来，而音频还在响：表现就是「播放窗口不可见，也没暂停」。

顺带一个哑巴亏：1×1 的子窗口始终 `WS_VISIBLE`，等于每次切页都还留着一个像素级的脏点，而且 mpv 仍在往一个 1×1 的 surface 上画。

## 2. 改法

### 2.1 内核：把「可见性」变成显式状态（pf-mpv / pf-core）

- `Inner` 增 `surface_visible: AtomicBool`（默认 `true`）；
- `MpvHost::set_surface_visible(bool)`：写意图 + 立即 `ShowWindow(SW_SHOW/SW_HIDE)`；
- `MpvHost::surface_visible()` 读取意图；
- `show()/hide()` 保持**裸显隐**语义（不动意图）—— `stop()` 继续用它收起画面，避免「停止播放」把用户意图误置成不可见；
- `load()`：`loadfile` 成功后**仅在意图可见时**才 `show()` —— 这条是给「在别的页面上自动连播下一集」兜底的：过去 `mpv.load` 的 RPC 处理里硬编码 `host.show()`，切页后连播会把视频窗口重新弹出来盖住媒体库。

新 RPC `mpv.visible {visible: boolean}` → `{visible, attached}`：

- 已挂接：写意图 + 生效，返回 `attached:true`；
- 未挂接：返回 `attached:false` 而非 JSON-RPC error —— 调用方是「切页钩子」，不该被「还没起播过」打断。

### 2.2 前端：意图入 store，切页驱动显隐（player.ts / PlayerView.vue / DanmakuLayer.vue）

- `player.surfaceWanted: boolean`（默认 true）：**意图**而非状态，与播放状态彻底解耦；
- `player.setSurfaceWanted(visible)`：只记意图（是否在播放页），哪怕当前是 hls 内核 / 尚未 attach；
- `player.mpvPushSurface(visible)`：只落 `mpv.visible` RPC，不改意图。**意图与「当下该不该显示」必须分开**：回到播放页时意图是可见，但按过「停止」就不该弹出一块空黑窗口；
- `store.playMpv()`：`attach` 之后、`loadfile` **之前**按意图校准一次 —— 既防止「在别的页面上自动连播」把原生窗口弹出来盖住媒体库，也保证「停止后再播」能重新显示画面；
- `PlayerView.applySurface()`：watcher 盯 `[route, engine]`（**刻意不含 `mpvReady`**：它首次翻 true 就在 `playMpv` 内部，再推一次会和 playMpv 的校准打架）。离开播放页 `mpvPushSurface(false)`；回来在有内容（`playing || eof`）时 `mpvPushSurface(true)` + `nextTick` / 80ms / 320ms 三拍重对齐矩形（`v-show` 恢复时布局要几拍才稳定）；
- `syncMpvRect()` 双守卫：`route !== 'player'` 早退、`rect < 2px` 早退 —— 从根上不再有「0 矩形写进 mpv.move」这条路。

### 2.3 覆盖层（P17 链路）同步收起

透明覆盖层是 owner 挂主窗口的**独立顶层窗口**，同样不吃 `display:none`：切页后弹幕会继续飞在媒体库/设置页上面。`DanmakuLayer` 增 route 监听：离开时 `overlayEnabled(false) + overlayHide()`，回来 `syncOverlay()`（幂等全量重推，顺带 show）。

另有 `mpv.visible` 的 headless RPC 冒烟 6/6（未挂接、attach、hide/show 往返、detach）。

构建：`pnpm -r typecheck` / `pnpm -r build` / `cargo build --release` 全绿。

## 4. 踩过的坑（供后续参考）

1. **测试片时长必须够**：第一版用 MDN `flower.mp4`（约 5.5s），断言跑到一半片子已 eof，`pause=yes` 被误判成「被暂停」。第二个坑同理：起播检测循环（1s 轮询 + PowerShell 取证）本身要吃掉几秒，10s 片子在第一次采样时已到 9.97s。最终方案：起播确认后**先 seek 到 0 并解除暂停**，再进入「离开 → 回来」的测量段。
2. **`pause=yes` 不等于被暂停**：需要同时看 `paused-for-cache`（缓存等待）与 `eof-reached`（`keep-open=always` 播完停住），否则会把正常状态判成 bug。
3. **PowerShell 要从 node 里以绝对路径拉起**：沙箱里 `powershell` 不在 PATH（`spawnSync powershell ENOENT`），需 `process.env.SystemRoot + '\\System32\\WindowsPowerShell\\v1.0\\powershell.exe'`。
4. **不要把「隐藏」实现成「暂停」**：mpv 子窗口隐藏后解码/音频继续是需求本身，任何 `pause`/`stop` 都会违背「也不要暂停播放」。
