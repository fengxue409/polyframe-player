# P43 采集分页链路排查与修复

> 症状：片库「就这么多片子」，很多片搜不到、翻不到；分类筛选后更少。
> 结论：**不是源站少，是分页链路有三处断点** —— 首页从不翻页、内核不用 `pagecount` 判终止、
> 每页只要 20 条。修完后同一批源站单页覆盖 60 → 150 条（25 站聚合），且能真正往后翻。

## 1. 链路现状（实测，2026-11-03）

对 15 个预设站直连 `ac=detail&pg=N` 取证（`.probe/page-audit.mjs`）：

| 源站 | 每页条数 | pagecount | total | 首页实际会取到 |
|---|---|---|---|---|
| 非凡资源 | 20 | 4946 | 98 915 | 20 |
| 暴风资源 | 20 | 8518 | 170 357 | 20 |
| 极速资源 | 20 | 5781 | 115 619 | 20 |
| 百度资源 | 20 | 2477 | 49 531 | 20 |
| 无尽资源 | 20 | 6211 | 124 209 | 20 |

也就是说：源站侧每个站还有 **2 000–8 500 页**没被请求过。

搜索更极端 —— `wd=爱` 在非凡站：`total=1195 / pagecount=60`，而旧代码只取第一页（20 条）。

旧链路（修前）：

```
首页 load()  ──rpc catalog.category{pg:1}──▶  内核：18 站各请求 1 页（每页 20）
                                              ↓ 本地按 type/year/area 过滤
                                              ↓ 聚合去重 → 排序 → truncate(60)
                       ◀── cards(≤60), hasMore = cards.len() >= 20
   没有「加载更多」，也没有第二次 rpc
```

## 2. 五个断点

### ① 首页从不翻页（结果偏少的主因）

`HomeView.load()` 固定 `buildCategoryParams(filters, 1)`，全页面没有任何 `pg+1` 的路径。
`hasMore` 虽然回来了，但没人消费。片库再大，首屏永远只有这一页聚合出的 ≤60 部。

### ② `hasMore` 用「筛后条数」猜，条件一窄就变成「已到底」

```rust
// 旧
let has_more = cards.len() >= 20;   // cards 是**已按 category/year/area 过滤并去重**后的数量
```

`类型=综艺 + 地区=日本` 时，一页 18×20 条筛完可能只剩 3 条 → `has_more=false`，
用户看到「没有更多了」，而源站其实还有 5 800 页。

### ③ `pagecount` 被解析但从未使用

`cms.rs` 里 `CmsResponse` 有 `page` / `pagecount` / `total`，但 `parse_vod_list()`
只返回 `list`，把三个字段丢了。后果：

- 没有权威终止条件，只能靠条数猜；
- 一个忽略 `pg` 的站（永远回第 1 页）不会被发现，翻页等于原地踏步；
- 无法「按需多翻几页」补齐窄筛选。

### ④ 搜索没有页码

`search_url()` 不带 `pg`，`search()` 固定取第一页，再聚合 `truncate(60)`。
1195 条命中只取 20 条/站 → 聚合后 60 条，剩下 95% 永远拿不到。

### ⑤ 追加没去重

`catalog.loadCategory(false)` 是 `[...this.catCards, ...r.cards]`。内核每页**现算**聚合表
（跨页无记忆），站内更新流抖动、忽略 `pg` 的站都会把同一条再给一遍。
实测首页 pg1+pg2 有 **6/60** 重复；搜索也有 5/60。

### 另外两个「看起来像结果少」的配置

- `SOURCE_TIMEOUT = 4s`：`ac=detail` 一页带 `play_url`，实测常态 0.6–2.0s，
  冷启动（DNS+TLS+50 条）能到 4.8s —— 4 秒会把「慢但能用」的站整页判失败，
  那一页直接少一个站。
- RPC 客户端 `REQUEST_TIMEOUT_MS = 10s`：单源 9s × 搜索回退 2 连发 / 填页 3 页都会超。

## 3. 修复

### 内核 `pf-parser/src/cms.rs`

- 新增 `PAGE_SIZE = 50`，`page_url()` / `search_url()` / `search_url_at()` 全部带
  `pagesize=50`。实测 15 个预设站：11 个生效（回 50 条），4 个忽略（仍回 20，不报错），
  0 个失败 —— 安全。猫眼默认 30，也一并为 50。
- 新增 `VodPage { items, page, pagecount, total }` + `parse_vod_page()`；
  `parse_vod_list()` 保留为薄包装（探测/详情/追更仍用它）。
- 新增 `VodPage::has_next(requested_pg) -> Option<bool>`：
  空列表 → `false`；有 `pagecount` → `page >= pagecount` 即到底；站不给该字段 → `None`。

### 内核 `pf-core/src/catalog.rs`

- **填页循环**（`CAT_PAGE_WINDOW = 3`）：一次 RPC 内最多连翻 3 页，边翻边聚合，
  一旦候选数够 `need`（`limit+10`，带评分/站数门槛时 `limit*3`）或所有站到底就停。
  常见情况（无筛选）第一页就满足 → 请求数与改造前相同；只有窄条件才会多翻。
- `hasMore` 改为真实终止判断：`got_any && 还有站没到底`。全部源站失败时恒 `false`，
  避免前端无限「加载更多」。
- 响应新增 `pages`（本次消费了几页），`page` 改为**实际消费到的最后一页**，
  客户端用 `page+1` 续翻，不会跳页。
- 搜索支持 `pg`（clamp 1..200）+ `limit`，`hasMore` 同源站 `pagecount` 判定，
  缓存键加入页码（否则第 2 页命中第 1 页缓存）。
- 页缓存键改为 `api|pg|hours|pagesize`（换每页条数后旧缓存语义不再成立）。
- `accumulate()` 同站同 `vod_id` 只记一条 `EntryRef`：翻页重叠不再把「6 站收录」算成 12 站。
- `SOURCE_TIMEOUT` 4s → 9s。

### 前端

- `catalog.ts`：`loadCategory` 从「加载中直接丢弃」改为**请求序号**（`catSeq`，后来者覆盖），
  追加时用 `mergeCards()` 按聚合键去重。旧写法会让「加载中改条件」的那次请求被静默吞掉。
- `HomeView`：新增 `page / hasMore / moreLoading / loadToken`，`loadMore()` 走
  category 或 search，页码以**内核回显**为准；底部新增「加载更多 · 已显示 N 部 · 源站还有更多」
  与按钮（`.more-row`），演示数据/收藏视图不显示。
- `rpc.ts`：`REQUEST_TIMEOUT_MS` 10s → 35s（填页 3×9s、搜索回退 2×9s 都覆盖）。

## 5. 已知边界

- `pg` 上限 500（category）/ 200（search）。按 50 条/页算 ≈ 2.5 万条，正常浏览够用；
  要「扫全库」得走巡检/追更，不是浏览路径的职责。
- 跨页仍有低比例重叠（6/60）：源于站内排序抖动与个别忽略 `pg` 的站，前端去重兜住。
- 4 个站忽略 `pagesize`（无尽/最大/U酷/百度），仍按 20 条/页返回；`pagecount` 也是按它们
  自己的页大小算的，所以**终止判断不受影响**。
- 聚合键是 `片名|年份`：同一部片若某站年份为空，会与有年份的那条分成两张卡 —— 属既有
  聚合策略（不做模糊聚类，P33 已定），不在本批范围。
