# P20 播放页信息侧栏 — 交付总结

> 2026-10-30 · 范围：播放页信息侧栏（标题/简介/剧集/线路/来源）+ 就地选集 + 上下文贯通
> 验证：`e2e-p20` **27/27**（真窗口 + CDP 取 DOM 矩形与截图）/ typecheck + build 全绿

## 1. 缘起

选集起播这条链路此前是「断了」的：详情弹层点某集 → `playFromQueue` → 建任务 → `route='player'`，
播放页里**只剩一块视频**。用户在弹层里看过的简介、年份、来源、还有那一整屏剧集，
一进播放页就全没了；想换第 8 集得切回发现页重新搜、重新开弹层。

所以本批不是「给播放页加个详情卡」，而是把**起播上下文**沿调用链带进播放页，并让它成为选集入口：

- 详情弹层的组头「N 集」本身变成起播按钮（▶ 从第一集连播）
- 播放页右栏承载这部剧的全部信息与剧集网格，换集不再跳页

## 2. 交互决策（每条都是权衡后的选择，不是默认值）

| 场景 | 决策 | 理由 |
|---|---|---|
| 默认状态 | `innerWidth ≥ 1180` 展开；更窄默认收起 | 侧栏 336px，窄屏默认展开会把播放器挤成邮票 |
| 记忆 | `localStorage['pf.playerSide']`（`1` 展开 / `0` 收起） | 用户手动切过一次就以用户为准，不因窗口尺寸变化被反复抢走 |
| 收起形态 | 56px 竖条：展开按钮 + 迷你海报 + **竖排片名** + `2/12` 集序徽章 | 收起不等于「消失」，要让人一眼知道在放什么、放到第几集；竖排是在 56px 里塞下片名的唯一办法 |
| 窄屏（≤900px） | 侧栏落到**播放器之后、调试面板之前**，不再 sticky；收起态压成一行摘要 | 调试面板是配角，不该把视频信息挤到页面最底部（所以用 grid 而不是两层 flex，见 §3.2） |
| 切集 | 就地换集，不跳页不卸载；当前集高亮 + 自动滚进可视区 + 顶部「上一集/下一集」 | 队列 100 集时，「当前集在哪」比「列表有多长」重要 |
| 播放进度 | 切集前 `flushProgress()` 立刻落库（不等 5s 节流） | 否则「看到 41:30 换集」最后几秒白看，继续观看会退回到 41:20 |
| 同集点击 | 不重建任务，直接续播 | 重建任务 = 重新拉流 + 进度归零，是对「点了没反应」的错误修复 |
| 线路切换 | 按**集名**对齐尽量停在同一集 | 换线路不该把用户打回第 1 集 |
| 加载 | 「正在切换第 N 集…」+ 所有集按钮禁用 | 换集有建任务 RPC，几百毫秒的空窗期必须可见且不可重复点 |
| 异常 | 侧栏内联错误条 + 「重试」；不弹 toast 不跳页 | 播放页已经黑屏报错过一次，侧栏再弹个浮层只会更乱 |
| 无上下文 | 空态引导「去发现页选集」 | 与「直链播放」区分：正在放东西时提示「去发现页」是误导（见 §3.4） |

## 3. 实现

### 3.1 播放上下文 `PlayContext`（catalog store）

`playCtx` 是**起播方写给播放页的一份快照**，不是一个需要回源查询的懒加载对象：

```ts
interface PlayContext {
  title; subtitle?; poster?; content?; year?; typeName?; remarks?;
  actor?; director?; siteName?; api?; vodId?;
  groups: CatalogEpisodeGroup[];   // 线路分组快照
  groupIndex: number;              // 当前队列属于哪条线路
  favoriteId?; startedAt: number;
}
```

为什么传快照而不是让播放页按 `api+vodId` 回源：P19 虽然有详情缓存，但**收藏 / 网盘 / 直链三种起播根本没有 api**；
起播方（详情弹层、收藏弹层、继续观看）手里现成有全量信息，传一次最省事也最不会错。
`contextFromDetail()` / `favoriteContext()` 两个构造函数统一了来源差异。

### 3.2 布局用 grid，不是两层 flex

```css
.player-view {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 336px;
  grid-template-areas: 'player side' 'debug side';
}
@media (max-width: 900px) {
  .player-view { grid-template-areas: 'player' 'side' 'debug'; }
}
```

第一版是 `flex: row` + 左侧 `player-col` 包住播放器与调试面板，结果窄屏时侧栏被顶到调试面板之后
（因为它只能排在整列之后）。改 grid area 后，窄屏顺序变成 player → side → debug，一行代码解决。
`side-collapsed` 把第二列压到 56px，播放器随之变宽（E2E 实测 872px → 1138px）。

### 3.3 选集与进度

- `playAt(index, force?)`：队列第 N 集起播；**同集且正在播放时直接返回 false**（调用方据此走 `resumeCurrent()`）。
- `switchPlayGroup(gi)`：换线路，按集名找对齐位置，找不到回第 1 集。
- `playNext()` 退化成 `playAt(queueIndex + 1, true)`，自动连播与手动选集共用同一条路径。
- `flushProgress()`：hls 读 `video.currentTime/duration`，mpv 读 `mpvState`；切集/切线路前调用一次并把节流时间戳更新，
  避免「刚上报过 → 切集时被节流吞掉」。

### 3.4 上下文失效：谁会把侧栏写脏

除片源选集外还有 5 条起播路径，各自处理：

| 起播方 | 处理 |
|---|---|
| 详情弹层 / 收藏 / 继续观看 | `playFromQueue(..., ctx)` 带全量上下文 |
| 解析页 / 首页演示卡 | `setLooseContext(title, '解析直链'/'演示片源')`：有标题、无剧集 |
| 网盘「在线播放」/ 磁力播放 | `setLooseContext(文件名, '网盘'/'磁力')`（这两条 `sourceTaskId=''`，不会触发任务 watcher） |
| 媒体库 / 任务页 / 网盘「加入任务」 | 播放页 watch `sourceTaskId`：新任务的 `url` 不等于当前队列集、且标题与已有上下文不同 → `setLooseContext(t.title, '本地任务')` |
| 手输 URL 点「播放」 | `catalog.clearQueue()` → 回到空态 |

「直链播放」用 `setLooseContext` 而不是清空，是为了区分**空态**（从没播过）和**无剧集信息**（正在放直链）：
后者给的是「该片源没有剧集列表」，不是「去发现页选集」。

### 3.5 mpv 子窗口

侧栏收缩会改变 `.video-wrap` 宽度。`ResizeObserver` 已经兜住，但首帧未布局时 rect 可能是旧值，
所以 `setSide()` 里额外补一拍（`nextTick` + 120ms）重推 `mpv.move` —— 与 P18 切页回补三拍同源。

## 4. 验证（`apps/core/scripts/e2e-p20.mjs`，27/27）

真 Electron 窗口 + CDP：注入 `playCtx`（等价于弹层起播写入的状态）后按 DOM 矩形断言，并留 3 张截图。

- **展开态**：侧栏宽 336、在播放器右侧；标题「星际穿越」、`第 2/12 集`、`来源：测试采集站`、
  12 个剧集按钮且只有 1 个 `.active`、2 个线路 chip、3 个元信息 tag、简介 79 字、进度条与状态文案就位
- **收起态**：宽 56、出现 `.rail-btn`、竖排片名「星际穿越」、徽章 `2/12`、`localStorage=0`、播放区 872 → 1138
- **展开回来**：宽 ≥ 300
- **点第 4 集**：`queueIndex=3`，高亮与「第 4/12 集」同步，无错误条
- **切第 2 线路**：`groupIndex=1` 且仍停在第 4 集（按集名对齐）
- **窄屏 760px**：侧栏 `top` 在视频区下方（stacked）且宽度与视频区一致
- **直链上下文**：标题「解析出来的片子」、来源「解析直链」，无剧集列表时不显示选集引导
- **空态**：出现「还没有正在播放的影片信息」

## 6. 已知限制

- 侧栏剧集列表来自**起播时的快照**：追更在后台加了新集，侧栏不会自己长出来，需回发现页重新打开（P19 详情缓存有 30min TTL，重开很快）。
- 播放页内不支持「换片源」（跨站换源）：那需要 `detailCard.entries`，而继续观看 / 收藏场景没有这份数据，留给后续批次在侧栏做「换源」入口。
- 侧栏不做弹幕开关等播放控制的镜像，控制仍然只在播放器控制条上。
