# P13 交付总结：追更间隔可配置 + 热门榜叠加 TMDB 人气（GYING 吸收尾巴收尾）

## 背景

P11 交付时留了两个小尾巴，本批收掉；GYING 吸收清单至此全部完成（磁力 P12 另见 `P12-交付总结.md`）。

## 1. 追更巡检间隔可配置

- **RPC**：`catalog.favorite.autoscan` 新增 `intervalHours` 参数（0 = 关闭，1–72 小时；越界报「巡检间隔需在 0–72 小时之间」）；返回值实时回读落库值
- **内核**：main.rs 巡检循环从「固定 sleep 6h」改为 **5 分钟 tick 轮询设置**——改间隔无需重启内核；关闭态空转等待，恢复后按间隔重新计时；`autoscan_interval_hours()` 统一读取（settings 键 `catalog.autoscan.interval_hours`，默认 6h）
- **前端**：媒体库收藏 tab 新增「自动巡检」间隔下拉（关闭 / 1 / 3 / 6 / 12 / 24 / 72 小时），与巡检状态文案并排

## 2. 热门榜叠加 TMDB 人气

- `catalog.category` `sort=hot` 且配置了 TMDB Key 时：对站数粗排后的**前 30 名**并发查 TMDB（每批 12，与导入并发同参），取 `popularity` 参与加权排序：
  `score = source_count + min(popularity / 10, 20)`——站数仍是主导，人气在同分片内决胜（pop 封顶 +20，防止单站高人气片压过多站聚合片）
- 卡片附 `tmdb: { rating, popularity }`（未命中不带字段）；前端热门模式卡片显示「★ 评分」徽章（替代更新日期角标）
- **缓存**：进程内 24h TTL（`name|year` 键，懒清理），翻页不重复打 TMDB；未命中不缓存（下次可重试）
- **降级**：无 Key / 请求失败 / 无命中 → 纯站数排序，全链路静默
- **测试基建**：TMDB API 基址支持 `PF_TMDB_API` 环境变量覆盖（冒烟用本地假站）

## 改动范围

- pf-core：catalog.rs（autoscan 间隔读写、TmdbPop + `tmdb_search` 抽取共用、pop 缓存、热门加权排序）、main.rs（巡检循环重写）
- pf-proxy：**修复** `Receiver: Stream`——tokio 锁刷新到 1.54 后内置 Stream 实现已不存在，`rx.map` 改为 `ReceiverStream::new(rx).map(...)`，workspace 新增 `tokio-stream = "0.1"` 依赖
- shared：`CatalogCard.tmdb?`、`TmdbPop`、autoscan params `intervalHours`
- 前端：catalog store（`setAutoScanInterval`）、LibraryView（间隔下拉）、DiscoverView（评分徽章）

- **Cargo.lock 刷新风险**：`target/*/.cargo-build-lock` 残留（10/25 旧锁）导致 `cargo: failed to open … os error 5`，删锁即恢复；锁刷新顺带把 tokio 升到 1.54，暴露了 pf-proxy 对已移除的 `Receiver: Stream` 内置实现的依赖（已修复，见上）
