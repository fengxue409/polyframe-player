# P48 播放页键盘快进 / 快退

> 需求：播放页按 ← 后退、→ 前进；明确每次调整的时间步长；只在播放页生效，
> 不影响其它页面的键盘操作。

## 1. 按键与步长

| 按键 | 动作 | 步长 |
|---|---|---|
| `←` | 后退 | **5 秒** |
| `→` | 前进 | **5 秒** |
| `Shift` + `←` / `→` | 大步后退 / 前进 | **30 秒** |
| `Ctrl` / `Alt` / `Meta` + 方向键 | 不处理 | 留给系统与其它快捷键 |

- 5 秒的理由：40 分钟一集约 480 次步进 —— 够细，能退回「刚才那句台词」；够粗，连按十几下能跳过片头。
  1% 时长（原生时间轴的默认行为）在长剧集上是 24 秒，粒度太糙且随片长漂移。
- 位置一律 clamp 到 `[0, duration - 0.05]`：到 0 不越界，到片尾不会直接触发 `ended` 把剧集切走。
- 每次跳转弹一条 1.1s 的提示：`快进 5s · 01:23 / 42:10`，位于视频区底部居中、原生控制条上方，
  `pointer-events: none` 不挡操作。

## 2. 只在播放页生效

播放页是 `v-show` 保活的（`App.vue`：`<PlayerView v-show="store.route === 'player'" />`），
**组件永远挂载着**，所以「监听只在播放页生效」不能靠挂载/卸载，必须在处理器里显式判：

```ts
if (store.route !== 'player') return
```

另外两类必须让路的输入：

1. **输入框 / 下拉 / 可编辑区**（`input`、`textarea`、`select`、`isContentEditable`）——
   直链输入框里 ← / → 是移动光标，倍速下拉里是切选项，不能被抢。
2. **调试抽屉打开时**（`debugOpen`）—— 浮层里有输入框。

离开播放页时还要主动 `videoEl.blur()`（见 §4.3），否则方向键会继续在首页偷偷 seek。

## 3. 关键：必须 preventDefault

原生 `<video controls>` 的时间轴在键盘焦点下自带一条默认动作：**每次 ← / → 跳 1% 时长**。
不拦住就会变成「5s + 1%」双跳，而且这个 1% 随片长变化，用户会觉得键盘跳转时快时慢。

所以处理器里 `e.preventDefault()`，并挂在 **window 的捕获阶段**（`addEventListener('keydown', onSeekKey, true)`）：
捕获阶段最早，能保证在原生控件处理之前拿到事件。

## 4. 三个已踩过的坑

### 4.1 点过原生控制条之后，window 收不到任何键盘事件

这是本批最费时间的发现，全部有探针实证（`.probe/probe48-diag.mjs`、`.probe/probe48-fix.mjs`）：

| 操作 | `document.activeElement` | `video.matches(':focus')` | window 上的 keydown / pointerdown |
|---|---|---|---|
| 点画面 | `VIDEO` | `true` | 收到 |
| **点进度条** | `VIDEO` | **`false`** | **一个都收不到**（捕获 + 冒泡计数均为 0） |

点进度条后焦点钻进媒体控件的 **closed shadow tree**，那个状态下：
`window` / `document` / `video` / `.video-wrap` 上的 `pointerdown` 也全部收不到，
`keydown` 同样——所以**无法用「pointerup 后抢回焦点」这种常规做法**，连事件都没有。

可用的补救：`video.focus()` 能把焦点拉回宿主（实测 `matches(':focus')` 变 true，随后 keydown 立刻恢复）。
触发点只能挂在「这个状态下必然会发生的媒体事件」上，统一收在 `reclaimVideoFocus()`：

```ts
function reclaimVideoFocus(): void {
  const v = videoEl.value
  if (!v) return
  if (document.activeElement === v && !v.matches(':focus')) v.focus({ preventScroll: true })
}
```

绑在：`seeking`（点/拖进度条）、`play` / `pause`（点播放按钮）、`volumechange`（点音量）、
`fullscreenchange`（点全屏）、`pointerdown`（点画面，通常已自动聚焦，兜底）。

### 4.2 mpv 状态回填有 ~250ms 空窗 → 连击必须累积落点

mpv 的 `timePos` 由状态泵回填，周期约 250ms。按住方向键时若每次都以「真实播放位置」为基准，
会一直落在旧值上，表现成「按了没反应」。所以维护连击锚点：

```ts
const chained = seekAnchor !== null && now - seekAnchorAt < 700
const base = chained ? seekAnchor : tl.pos
```

同时提交节流 120ms（键盘 auto-repeat 约 30 次/秒，不节流会把 mpv 的 RPC 打穿）：
窗口内只累积目标位置，窗口结束时一次提交，累积量不会丢。

### 4.3 v-show 隐藏不等于失焦

切到首页后 `video` 只是 `display:none`，焦点并不会自动释放；如果焦点还在原生控制的 shadow 里，
**display:none 也不解除原生键盘处理** —— 实测在首页按 → 视频仍然 +0.2s（1%）。

修法：路由离开播放页时在 `applySurface()` 里 `videoEl.value?.blur()`。

## 5. 实现位置

| 位置 | 内容 |
|---|---|
| `components/PlayerView.vue` | `KEY_SEEK_*` 常量、`seekTimeline()`、`commitSeek()`、`flushSeek()`、`nudgeSeek()`、`inEditableField()`、`onSeekKey()`、`reclaimVideoFocus()`、`showSeekHint()` |
| 同上 · 模板 | `<video>` 增 `@play/@pause/@volumechange/@pointerdown`；`.video-wrap` 内增 `.seek-hint` |
| 同上 · 样式 | `.seek-hint`（黑底白字胶囊，`pointer-events:none`，`z-index:6`；**不给 `.video-wrap` 加 overflow**，P38） |
| 同上 · 生命周期 | `onMounted` 注册 window keydown(capture) 与 `fullscreenchange`；`onBeforeUnmount` 移除并清定时器 |

引擎无关：`seekTimeline()` 按当前内核取时长与位置，`commitSeek()` 分两条路径
（hls 写 `video.currentTime` + 同步弹幕；mpv 调 `mpvSeekTo` 并先喂弹幕引擎）。

## 7. 已知限制

- **mpv 内核未实测**：本机没有 `libmpv-2.dll`。代码路径已按 `mpvState.duration` / `mpvSeekTo` 写好，
  但「mpv 原生子窗口是否吞掉键盘」需要装好 DLL 后补测；若被吞，得在主进程转发按键。
- 焦点被主动收回 `<video>` 后，原生控制条内部的键盘操作（用键盘调音量滑块）会被打断；
  播放器本来没做键盘无障碍设计，这里按「方向键优先」取舍。
- 长按方向键的重复速率由操作系统决定（约 30 次/秒），我们只做 120ms 节流，不自己造 repeat。
- 直播流（`duration` 为 0 / Infinity）不响应：往回跳没有意义。
