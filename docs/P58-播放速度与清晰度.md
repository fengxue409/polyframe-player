# P58 全屏控制条：左侧图标化 + 倍速 / 清晰度

> 需求：在现有进度条基础上补控制功能 —— 播放速度调整、分辨率切换，并优化左侧布局。
> 左侧控件尽量用图标，每个图标给悬浮提示；间距与对齐要合理，风格与现有进度条一致，
> 窄屏下不显拥挤。

拆成六条可验收的硬指标：

| # | 指标 | 落点 | 复核 |
|---|---|---|---|
| ① | 左侧图标化成组 | `.fs-transport` 三键（上一集 / 播放暂停 / 下一集） | `p58.transportTips` |
| ② | 每个图标带悬浮提示 | `data-tip` + 自绘 `::after` | `p58Tip` + `tip.png` |
| ③ | 倍速调整 | `.fs-chip` 胶囊 + 8 档列表 | `p58Speed`（`rate:1.5`） |
| ④ | 分辨率切换 | 解析 master → 列档 → 重载续播 | `p58Variants` |
| ⑤ | 间距对齐、风格一致 | 组内 2 / 组间 12；全部 `cy=1055` | `p58.cys` / `p58.gaps` |
| ⑥ | 窄屏不拥挤 | 两档媒体查询 + 实测两档视口 | `p58Narrow` |

## 1. 控制行结构：从「八个文字块」到「三组」

改前的控制行是 8 个平级元素挤在一个 flex 里：`▶ 暂停` `⏮ 上一集` `⏭ 下一集`
`00:12 / 01:30` `[轨道]` `🔊 ▬▬` `☰ 选集` `⛶ 退出全屏`。三个传输按钮各带文字，
光是字就吃掉 200 多 px，再塞进两个新胶囊必然把轨道压瘪。

```
改前  [▶暂停][⏮上一集][⏭下一集] 00:12/01:30 [======轨道======] [🔊 ▬▬] [☰选集][⛶退出全屏]
改后  [⏮][▶][⏭] 00:12/01:30 [====轨道====] [1.0×][720P] [🔊 ▬▬] [☰选集][⛶]
        └─ 图标组 ─┘                          └值胶囊┘          └──────── 图标 + 少量文字 ────────┘
```

三条规则，改宽度时别破坏：

1. **图标组自己成组**（`.fs-transport`，组内 `gap: 2px`）——三个键属于同一类操作，
   组内贴紧、组外跟别人一样吃行 gap，靠间距把「一组」表达出来，不需要画分隔线。
2. **轨道是唯一伸缩项**（`flex: 1`），其余 `flex: none`。所以窗口变窄时只有轨道缩，
   按钮、时间、胶囊一个都不许被挤动 —— 这是 P55 定下的，P58 加控件时继续守住。
3. **数字用 `tabular-nums`**。`00:12 / 01:30` 与 `1.25×` 都是会变化的数字，
   等宽数字保证「数字变了但位置不变」，否则每换一秒整行抖一下。

实测（1920×1080 全屏，`p58`）：

| 元素 | 左 | 右 | 宽 | 中线 cy |
|---|---|---|---|---|
| `.fs-transport` | 20 | 108 | 88 | 1055 |
| `.fs-time` | 120 | 192 | 72 | 1054 |
| `.fs-track` | 204 | 1418 | 1214 | 1055 |
| `.fs-chip`（倍速） | 1430 | 1490 | 61 | 1055 |
| `.fs-vol` | 1577 | 1610 | 100 | 1055 |
| `.fs-bar-acts` | 1702 | 1799 | 97 | 1055 |

`cy` 只有一个值 1055（时间文本基线差 1px 是字体度量，不是布局），行内 6 个 gap 全 12。

**为什么不用绝对定位让按钮「浮」在轨道上方**：P55 已经踩过 —— 一个
`align-items: center` 的 flex 就能让 30px 命中区和轨道细条天然同中线；
换成绝对定位就得手算 `top` / `translate`，字号一变就错位。

## 2. 悬浮提示：自绘，且要抬到条子外

```html
<button class="fs-icon" data-tip="上一集" aria-label="上一集">…</button>
```

```css
[data-tip]::after {
  content: attr(data-tip);
  position: absolute;
  left: 50%;
  bottom: calc(100% + var(--fs-pop-lift, 39px));  /* 注意是「条子上沿」不是「按钮上沿」 */
  translate: -50% 2px;
  opacity: 0;
}
[data-tip]:hover::after { opacity: 1; translate: -50% 0; }
```

三个决定：

- **不用原生 `title`**：1 秒才出、样式由系统画、在一条压暗的玻璃上是一块不协调的
  浅黄气泡。
- **`--fs-pop-lift` 与弹层共用同一个基准线**。按钮在 72px 条里只占中下 30px，
  只抬 8px 的话气泡正好压在**标题行文字**上（`星际迷航：破晓 第 9/42 集`），
  看起来像布局错位。抬 39px（= 标题行 16 + 行距 4 + 上留白 11 + 8）就整个浮到
  画面上，和弹层同一层语义。≤900px 时标题行隐藏、控制行上移到 21，这一值改 29。
- **`translate` 独立属性**而不是 `translateY()`：给 hover 的位移留出 `transform`
  通道，以后要加缩放不冲突（P56 的游标居中踩过这个坑）。
- 边缘兜底：行尾元素加 `.tip-end`（右对齐），行首加 `.tip-start`（左对齐）。
  窄屏条内 padding 收到 12px 时，行首的居中气泡会顶出视口左沿。

实测（`p58Tip`）：气泡底边落在条子上沿**之上** `8px`（`tipBottomFromBarTop ≈ -8`），
`opacity: 1`，内容 `暂停（空格）`；截图 `tip.png`。

## 3. 倍速：值胶囊 + 列表弹层

```html
<button class="fs-chip" :class="{ open: fsMenu === 'speed' }" data-tip="播放速度">
  <svg class="ico-chip">…</svg><b>{{ fsRateLabel }}</b>
</button>
<Transition name="pf-fs-pop">
  <div v-if="fsMenu === 'speed'" class="fs-menu">…8 档…</div>
</Transition>
```

- **不用滑杆**：档位是离散且互斥的（0.5 / 0.75 / 1 / 1.25 / 1.5 / 2 / 2.5 / 3），
  滑杆选不中精确值，还要额外做吸附。
- **不用原生 `<select>`**：全屏是 top-layer，原生下拉列表由系统绘制在 top-layer
  之上，配色与这条玻璃完全对不上（白底黑字，出现在一片压暗的画面上）。
- **胶囊宽度稳定**：`font-variant-numeric: tabular-nums` + `white-space: nowrap`，
  `1.0× → 1.25×` 不会把右边的清晰度胶囊推走。
- 文案：`1×` 看着像「第一档」，所以永远带一位小数（`1.0×`）；档位表里 1 倍标「正常」。
- 落到内核：`store.setPlaybackRate(r)`（hls 写 `video.playbackRate`，
  mpv 写 `speed` 属性）—— 与 P15 的倍速入口同一份状态，两处不打架。

实测（`p58Speed`）：菜单 8 项、高 277px、`aboveBar: true`、离条 8px；
点 `1.5×` 后 `video.playbackRate === 1.5`，胶囊文案同步 `1.5×`，菜单关闭。

## 4. 清晰度：解析 master，重载换档

### 4.1 为什么不在 hls.js 上 `currentLevel = n`

页内播放用的是 `playUrl` —— 代理本地化后的**单档 media playlist**（走下载引擎，
缓存 / 多源 / 解密全部生效）。它没有 variants，`hls.levels` 恒为 1，在它上面换档
是换不动的。

要拿到全部档位只有一条路：`task.masterUrl`（P3 就为多清晰度重写过的那份），
从中解析 `#EXT-X-STREAM-INF`，把**目标档重新载入一次**。代价是重载（丢缓冲），
换来的是「最高档仍然走下载引擎」这条不能丢的性质（其余档在代理侧是 `/raw` 透传）。

### 4.2 档位表与「当前是哪一档」

```ts
interface FsVariant { key, url, height, bandwidth, top }
```

`top` = 码率最高那档 = 代理本地化的 `playlist.m3u8`，也就是默认播的那档。

当前档识别三条分支，缺一条就会出现「菜单里一格都不高亮」：

| 分支 | 条件 | 处理 |
|---|---|---|
| ① 字面命中 | `store.url === v.url` | 直接返回该档 |
| ② playUrl 特例 | url 匹配 `/playlist\.m3u8$/` | 返回 `top` 那一档（代理本地化只做最高档） |
| ③ 正在播 master 本身 | `store.url === fsVariantsMaster` | 用**实际解码高度** `mediaH` 就近匹配（阈值 180px），匹配不上退 `top` |

③ 是手贴 master 直链的情形：hls.js 在内部按 ABR 选档，外部推不出来，
只能读 `video.videoHeight`。一个帧都没解出来（清单还在解析 / 分片不是真 HLS）时
`mediaH` 为 0，退回最高档 —— 那本来也是播放器的默认行为。

### 4.3 换档与续播

```ts
catalog.pendingSeek = resumeAt      // hls 在 canplay 里消费
store.url = v.url
await store.play(video)
// mpv 没有 canplay 这条路径：loadfile 落地后再 seek 一次
if (store.engine === 'mpv' && resumeAt > 0) setTimeout(() => store.mpvSeekTo(resumeAt), 600)
```

- **片尾 5s 内不折腾**（`at > 3 && at < dur - 5` 才续播）：否则换完立刻结束，
  看起来像「切完就停」。
- `watch(store.url)` 会清空档位表（源换了，表就作废），但**自己切档要放过**：
  `if (fsVariants.some(v => v.url === u)) return`。漏了这条，换一次档菜单就空了。

### 4.4 单档源的文案

- 没有 master：胶囊显示 `mediaH` 真实高度（`720P`），否则「原画」。
- 档位表只有一项：条目文案跟随胶囊（同一份 `realLabel`），meta 写「源仅一档」，
  `active + disabled`。
- 这一行是**常态**不是异常态：`:disabled` 会把它洗灰成「坏了」，所以
  `.fs-menu-item.active:disabled { color: var(--fs-ink) }` 把墨色还回去，
  用 `cursor: default` + 无 hover 表达「点不动」。

实测（`p58Quality` / `p58Variants`）：

```json
{ "items": [{ "text": "720P源仅一档", "disabled": true, "active": true }] }
{ "items": [{ "text": "720P当前", "active": true }, { "text": "1080P2.4 Mbps", "active": false }],
  "chip": "720P" }
```

（fixture master 声明 720/1080 两档却都指向同一份 720p 的 mp4，所以解码高度
就近匹配到 720P —— 这恰好验证了分支 ③ 用的是「真实解码高度」而不是「猜最高档」。）

## 5. 玻璃上的弹层：backdrop root 陷阱

**这是本批最容易翻车的一处，已经翻过一次。**

P57 把玻璃挂在 `.fs-bar` 本体上。`backdrop-filter` 会为**后代**建立 backdrop root ——
于是 `.fs-menu`（条的子元素）的 `backdrop-filter` 只能采样到条的背景，
采不到画面。表现：条子透得好好的，弹层却是一块死的实色板（探针 `aboveBar:false`
时肉眼就能看出这个差别）。

改法：玻璃本体挪到伪元素，条子的盒子本身保持透明。

```css
.fs-bar::before {
  content: ''; position: absolute; inset: 0; z-index: -1;
  background: linear-gradient(180deg, …30% → 55%);
  backdrop-filter: blur(22px) saturate(150%) brightness(0.55);
}
.fs-bar { /* 只留 border-top / 内高光，不再有 backdrop-filter */ }
```

弹层自己一层玻璃：`background: #090c13 64%` + `blur(18px) saturate(150%) brightness(0.62)`
—— 比条子略实（弹层里是密集小字，要更稳的底），但**不许再加**：加到 80% 以上
玻璃就退化成实色板，和条子脱节。

`@supports not (backdrop-filter)` 时兜底 `rgb(9 12 18 / .94)`。

## 6. 弹层与点击：三处必须显式处理

1. **点画面关弹层，但不能顺手暂停**。`onVideoClick` 是「点画面 = 播放/暂停」，
   关弹层的那一次 pointerdown 会连带触发它。所以 `onFsPointerDown` 里判断
   「点在画面且不在 `.fs-bar`」→ `swallowNextVideoClick()`（400ms 自动复位），
   `onVideoClick` 开头见标记就 `return`。
   实测：`beforePaused:false → afterPaused:false, menuClosed:true`。
2. **弹层开着不许自动收起**。`fsIdleBlocked()` 加 `fsMenu !== null`，
   否则 2.6s 后条子滑走，弹层跟着被拖走。
3. **弹层与选集面板互斥**。`toggleFsMenu` 开菜单时关面板，`toggleFsPanel`
   开面板时关菜单 —— 两个都从底部往上弹，叠在一起谁也读不了。

窗口隐藏时 CSS 过渡不会自己推进，探针必须在断言前用 `capturePage()` 逼几帧
（`settle()`），否则量到的是上一份菜单的残留（这个也踩过一次）。

## 7. 窄屏：两档压缩，压的是文字不是控件

| 断点 | 做什么 | 实测（CSS 视口） |
|---|---|---|
| > 1180px | 全量：胶囊带图标 + 文字、按钮带文字 | 1920：gap 12，轨道 1214 |
| ≤ 1180px | 胶囊去图标（`.ico-chip`）、按钮去文字（`.fs-act-label`），保留集数数字 `9/42`；gap → 8 | 1129：轨道 604，溢出 0 |
| ≤ 900px | 隐藏标题行（`.fs-bar-head`），gap → 6，条内 padding 20 → 12，音量滑杆 52px | 872：轨道 418，溢出 0，`--fs-pop-lift: 29` |

**压的优先级**：先压装饰（图标、文字标签），再压间距，最后才压轨道；
音量滑杆在 ≤900 只缩到 52px 但**绝不隐藏**（触屏没有 hover，藏了就再也调不出来）。
实测两档 `overflow: 0`（最右元素不出视口）、`cys` 只有一个值、`order: true`
（视觉顺序与 DOM 顺序一致，Tab 焦点不会跳）。

窄屏怎么测：全屏铺满整块屏幕，没法把窗口缩到 1100px。用
`webContents.setZoomFactor(1.7 / 2.2)` 顶替 —— 缩放把 CSS 视口按比例缩小，
媒体查询看到的就是 1130 / 873 两个真实窄视口，布局真的走窄屏分支，
只是像素被等比放大（截图依旧清晰）。**量完必须把 zoom 复位到 1**，
否则后续 `sendInputEvent` 的坐标全错。

## 8. 可读性：条内墨色与「选中行用白墨」

条内的 `--fs-ink / -dim / -faint / -shadow` 是 P57 定的（全局 `--text-dim` 在玻璃上
只有 2.3:1）。P58 补了两条：

```css
.fs-bar {
  /* 浅色主题的 --accent-ink 是深藏青（给白底用的），落在压暗的玻璃上直接消失 */
  --accent-soft: color-mix(in srgb, var(--accent) 24%, transparent);
  --accent-ink: color-mix(in srgb, #d3e0ff 94%, transparent);
}
.fs-menu-item.active { background: var(--accent-soft); color: var(--fs-ink); }
```

- **选中行用白墨而不是强调色**：强调色和它的洗底同色相，压在一起时字形反而比旁边
  未选中的行更糊。选中这件事由「底色 + 右侧『当前』/✓」两个信号表达，字要保白。
- 洗底 24% 而不是 30%：30% 在压暗的画面上像一块贴纸，24% 才是「洗」。
- 实测计算值（`p58Quality.colors`）：条目 `#e2e7f0 @ 94%`、元信息 `@ 67.7%`、
  脚注 `@ 80%`、洗底 `srgb(0.298 0.490 1 / .24)`。

> 小字在 1x 截图里永远显得比实际暗（1px 笔画 + 抗锯齿，峰值只到目标的 ~50%）。
> 判断「够不够亮」不要只看放大图，要么取计算样式，要么量峰值亮度 ——
> 这一版就是先被放大图误导了一次，最后靠 `getComputedStyle` 定的案。

## 10. 未做 / 遗留

- **手贴非 HLS 直链的「清晰度」恒为单档**：没有 master 就没有档位，胶囊只显示真实
  解码高度。这是信息真实性的下限，不做假档位。
- **非最高档走 `/raw` 透传**（不吃分片缓存）：脚注已用 `title` 提示，
  但没有做成菜单里的可见说明 —— 加上会让单档菜单从 2 行涨到 4 行。
- **倍速快捷键**（`[` / `]`）没做：控制条上没有可发现的入口，先不加隐藏功能。
- 打包产物未更新（本批只改了 `out/renderer`）；需要出安装包时记得先抬版本号。
