# P30 播放页调试面板改为底部停靠抽屉

## 1. 问题：调试面板被 sticky 播放卡整块盖住

P24/P25 的布局里，调试面板排在播放卡下方、与播放卡同处一个滚动流：

```
.content（唯一滚动条）
└─ .player-view  grid[stage | info-side]
   └─ .stage
      ├─ section.player   position: sticky; top: 0
      └─ section.debug    普通流
```

播放卡钉住不动，调试面板跟着页面滚。只要右栏（简介 + 剧集 + 来源）比左列高，页面就产生滚动空间，调试面板必然从播放卡底下滑过去。

`.layout-check` 量到的数据（滚动到底时的重叠量）：

| 用例 | 侧栏集数 | 修复前 |
| --- | --- | --- |
| `longside-1920x1009` | 60 | **-271px**（面板完全不可见） |
| `legacy-1920x1009` | 1 | -31px（P24 旧规则对照组） |

P25 把播放卡做大之后，问题反而更严重：卡越高，盖住的范围越大。展开调试面板（`debug-open`）时虽然取消了吸顶，但代价是视频跟着页面滚走——「边看边调」的场景直接失效。

## 2. 方案：fixed 底部停靠抽屉

调试面板脱离内容流，改成视口底部固定的抽屉：

- **收起态**：右下角一个胶囊「调试 · N 源 · M 条」，圆点颜色 = 最新一条日志的级别（不点开也能看出有没有报错）。不占版面、不参与布局。
- **展开态**：贴底全宽抽屉，头部（标题 + 统计 + 收起），内容仍为「多源监控 / 事件日志」两栏，窄屏自动并成一栏。抽屉内部允许自己滚动（它是工具浮层，不是视图内容）。
- **Esc 关闭**：浮层对键盘用户必须可退出。

### 为什么不是浮层盖住视频

`mpv` 内核下视频是 Win32 子窗口（`WS_CHILD`），永远盖在 renderer 之上。任何 DOM 浮层只要与视频区重叠，就会被原生窗口吃掉半块——这是 P18/P26 反复踩过的坑。所以抽屉不能"盖在视频上"，只能"让视频让位"。

### 高度预算：抽屉展开 → 视频等比缩小

`.player-view.debug-open` 把 `--pf-dock-h` 算进 `--pf-card-room`，`.video-wrap` 的宽度由新的高度预算反推，视频整体缩小，卡底停在抽屉顶上方约 30px：

```css
--pf-card-room: 144px;                                   /* 收起态：不再给面板留 50px */
--pf-dock-h: clamp(150px, 25dvh, 240px);                 /* 大屏给足，小屏让位 */
.player-view.debug-open { --pf-card-room: calc(var(--pf-dock-h) + 104px); }
```

104 = 顶栏 51 + 上留白 16 + 间隙 16 + 余量 21。

## 3. 顺带修掉的根问题：`--pf-card-chrome` 是猜的

P25 把「视频区以外的卡片高度」写死成 176px（mpv 222px），并加过 `DM_STATUS_ROW` 修正。但它永远追不上真实内容——浏览器模式提示条、弹幕未配置提示、「手动播放」折叠行，都能把实际值顶到 **300+**（实测 315px，浏览器模式 365px）。

估算偏小的后果是视频区按错误预算放大、卡片比视口还高，于是底部内容被压住。现在改成**实测**：

```ts
const diff = cardEl.height - videoWrapEl.height   // 与视频尺寸无关，不会和"宽度反推"形成循环
if (diff < 0 || diff > innerHeight * 0.7) return  // 视频被压成 0 的过渡帧当脏数据丢弃
measuredChrome.value = `${diff}px`
```

`ResizeObserver` 监听卡片与视频区，内容增减（折叠行展开、弹幕提示出现）、窗口缩放都重算。估算值只当首帧兜底。

## 4. 窄屏的坑：视频区被算成 0 宽

窄屏（≤900px）本来靠 `100%` 撑满列宽，但 `min(100%, 负值)` 会取 0——调试抽屉展开后预算变负，整个视频区消失（实测 `videoW=0`，画面全黑）。修复：窄屏 `.video-wrap { width: 100% }`，不再受 dvh 预算影响。

窄屏抽屉是覆盖式的（视频不压缩，因为宽度本来就被列宽卡死），高度单独放宽到 `min(45dvh, 320px)`——两栏此时已并成一栏，150px 只够看一两条日志，而多占的高度并不会挤压视频。卡片在下方可滚动查看，`.player-view.debug-open` 的 `padding-bottom` 保证滚到底时卡片底部能露出抽屉之上。

## 5. 回归判据（`.layout-check`）

`measure.js` 的判据从「调试面板顶 − 播放卡底 = 16」改为：

- `overlapMax` = 播放卡底 − 抽屉顶，**任意滚动位置必须 ≤ 0**（渲染上取 `max(0, …)`，所以恒为 0）
- `dockBottomGap` = 视口底 − 抽屉底 = 0（贴底）
- 收起态 `pillInView` = 胶囊在视口内
- 视频 `aspect ≈ 1.7778`（16:9 不被破坏）

结果：

| 用例 | vh | 重叠 | 抽屉贴底 | 视频 |
| --- | --- | --- | --- | --- |
| `deck-1920x1009`（收起） | 993 | 0 | — | 1196×673 |
| `deck-1366x768`（收起） | 768 | 0 | — | 796×448 |
| `debugopen-1920x1009` | 993 | **0** | 0 | 841×473 |
| `debugopen-1440x900` | 900 | **0** | 0 | 702×395 |
| `debugopen-mpv-1366x768` | 768 | **0** | 0 | 444×250 |
| `debugopen-420x860` | 860 | 0 | 0 | 252×142 |

overlap 从 -271 变为 0；视频 aspect 全部 1.7776~1.7778。

## 6. 已知权衡

- **展开抽屉时视频会变小**。这是「视频不滚动 + 面板不被遮挡 + 卡片其他内容 315px 都可见」三条同时成立的必然结果；真实的 1440×900 窗口下视频约 455×256，1280×720 下约 340×190。收起抽屉立即恢复。
- **极矮窗口**（< 620px，已低于应用的 `MIN_HEIGHT` 560）抽屉收到 150px，视频会被压得很小，此时播放卡本身也已退回普通流（既有规则）。
- **窄屏**抽屉是覆盖式，首屏会盖住卡片底部，滚动即可查看。
