# P56 全屏控制条：自动隐藏 + 音量调节

> 需求：底部栏支持自动隐藏（说明触发条件、显隐交互、过渡效果），并支持音量调节
> （说明入口、范围、静音、状态展示、跨设备可用）。

## 1. 自动隐藏

### 触发条件（必须同时成立才收起）

只在**全屏**下生效，且逐条排除「收起来会让人骂」的场景：

| 条件 | 为什么不收 |
|---|---|
| 非全屏（窗口模式） | 窗口模式用原生控制条，本就不接管 |
| 暂停中 | 用户正在看画面 / 找按钮，收起来只剩一块黑板 |
| 拖进度条 / 拖音量滑杆 | 手指还在控件上 |
| 选集面板展开 | 面板依附于控制条 |
| 正在换集（`picking >= 0`） | 有进度反馈要显示 |
| 播放报错（`store.playerError`） | 需要能点到「重新加载」 |

全部满足后，**无操作 2600ms**（`FS_IDLE_MS`）收起。指针停在控制条上时阈值延长到
**4200ms**（`FS_IDLE_HOVER_MS`）—— 用户可能在瞄准按钮，但**仍然会收**。

### 为什么是「心跳」而不是一次 setTimeout

收起与否取决于 6 项状态，早前的实现是「每次交互排一个 `setTimeout`，到点再判一次」。
这条路有两个必坏的口子：

1. **进全屏那一刻某状态还没同步**（`fsPaused` 还没被 `play` 事件纠正、`picking` 还在
   -1 之外、面板刚关），`kickFsBar()` 直接 `return`，计时器压根没排上；之后状态即使
   自己好了，也没有任何代码会来重建它 —— 表现就是**永远不收起**。
2. **`fsBarHover` 被当成硬阻止**：鼠标最后一次移动落在底部条上（很常见：看完控制条
   顺手把鼠标搁那），`hover` 就一直为 `true`，控制条永久亮着。

现在改成 400ms（`FS_IDLE_TICK_MS`）**心跳自检**：每拍重算 `fsIdleBlocked()`，
满足条件就按 `performance.now() - fsLastActive` 判断是否超时。状态一旦变好，下一拍
（≤400ms）就自己开始计时，不依赖「某次事件恰好触发」。

### 显示（唤醒）方式

任何一次全屏内的 `pointermove` / `pointerdown` / `wheel` 都会 `noteActivity()`：立即显示并
重置计时。键盘操作（`←/→` 快进、空格、Esc）同样唤醒 —— 它们本就会弹提示条，条被收着会显得割裂。

两个必要的校正：

- **指针归属用事件目标判断**（`e.target.closest('.fs-bar')`），不用 `pointerenter`/`pointerleave`
  配一对布尔：后者一旦丢了 `leave`（窗口失焦、指针飞出窗口、隐藏窗口不派发 hover）就永久
  卡在「停在条上」，控制条再也不收。
- **原地补发的 `pointermove` 要丢掉**：布局变化（条收起、画面长高）之后 Chromium 会给鼠标
  下方补发一次 `pointermove`，坐标与上次完全相同。把它当用户操作就会「收起 → 立刻唤醒」
  无限循环（每 2.6s 闪一下）。所以坐标不变直接 `return`。

状态变化（暂停↔播放、面板开关、起播完成、开始/结束拖音量、报错）仍走
`watch([...], refreshFsIdle)` 立刻重算一次，不必等下一拍。

### 过渡效果

```
收起：.fs-bar   translateY(100%) + opacity 0      200ms var(--ease)
      video     height: calc(100% - 72px) → 100%   同一条缓动、同一时长
      .danmaku-layer  bottom: 72px → 0             同上
      光标      cursor: none（全屏观影时鼠标停在画面上很碍眼）
展开：全部反向，同样 200ms
```

**画面必须跟着长高**：只藏条不改画面会留一条 72px 黑带，读起来像坏了。两者同缓动同时长，
所以「视频下沿」与「条的上沿」在整个动画期间始终贴合，视觉上是抽屉被推下去。

两个例外：

- `mpv` 内核不做高度过渡（`.engine-mpv video { transition: none }`）—— mpv 是 Win32 子窗口，
  只能整块 `SetWindowPos`，逐帧改矩形会让画面反复 reconfigure、闪烁。矩形在 `fsIdle` 变化时
  一次到位（`watch(fsIdle) → scheduleMpvRect`）。
- 进入全屏的第一帧**也不做**过渡：那时视频要从小窗尺寸长到全屏尺寸，带过渡会看到画面
  「从一个盒子里长大」。所以过渡挂在 `.fs-anim` 上，进全屏两帧后才置位。
- `prefers-reduced-motion: reduce` 下全部关闭过渡。

## 2. 音量调节

### 入口与结构

全屏控制条右侧，**喇叭按钮 + 72px 短滑杆常显**（不是 hover 才展开）：

```
[🔊] ━━━━━━━●──────      （.fs-vol：按钮 30×33 + 轨道 72×30 命中区）
```

常显是刻意的：触屏没有 hover，hover 展开在触摸设备上等于没有入口。常显在鼠标 / 触控 / 手写笔
上行为一致，且状态（当前音量）不用悬停就能看见。

### 范围与行为

| 项 | 实现 |
|---|---|
| 范围 | 0–100 整数，与 mpv `volume` 属性量纲一致（`volume-max` 默认 100） |
| 拖到 0 | 视为静音（图标切斜线、填充归 0） |
| 从 0 往上拖 | 自动解除静音（否则「拉到 60 还是没声音」） |
| 点喇叭 | 静音 ↔ 恢复；恢复回到静音前的音量（`volBeforeMute`），不是回到 100 |
| 点击轨道 | 直接跳到该位置（命中区 30px，按 5px 细条算会点不中） |
| 拖动 | `setPointerCapture`，拖出轨道也跟手；**松手才落盘**，mpv 侧 100ms 节流推送（尾随最新值） |
| 持久化 | `localStorage['pf.player.volume'] = {v,m}`，换集 / 换内核 / 重启都保持 |

### 状态展示（三处同源）

1. **图标三态**：播放中正常双弧（`fsVolume >= 45` 才画第二道弧）/ 单弧 / 静音斜线
   （静音或音量为 0 时切到斜线）。
2. **滑杆**：填充宽度 = `fsVolFillPct`（静音时为 0），游标位置同源；`aria-valuenow` 同步
   （静音读作 0），`aria-valuetext` 读 `已静音` / `40%`。
3. **文字**：`title`（`静音（当前 40%）`）、滑杆 `title`（`音量 40%`）、hover/拖动气泡 `40%`。

### 双内核

- hls：写 `video.volume` / `video.muted`；原生控制条上的音量变化经 `volumechange` 反向同步
  （拖动期间忽略回弹，否则拖到 30 会被自己写下去的值弹回 28）。
- mpv：`mpv.set volume`（0–100）+ `mpv.set mute yes|no`，由渲染层持有唯一一份音量
  （`MpvState` 不泵 volume）。起播完成 / 切内核时补推一次（内核刚起来是默认 100）。

## 3. 本轮修复：游标偏下

`.fs-rail-knob` 与 `.fs-vol-knob` 都写了 `top: 50%`，但**漏了垂直居中补偿**，而 `transform`
已被 `scale()` 占用、塞不进 `translateY(-50%)` —— 结果圆点的「顶边」落在轨道中线上，整个点
下移半个直径（12px 的点下移 6px、10px 的点下移 5px）。

改用独立的 `translate: 0 -50%`（与 `transform` 互不干扰，缩放动画照旧），两处游标中心与轨道
中心 cy 完全重合。

`@media (max-w: 900px)` 的窄屏断点里 `min-width: 0` 之类规则不影响此修复。

## 4. 实测（1920×1080，真实 Electron 窗口 + `sendInputEvent`）

```
自动隐藏：
  fresh       {idle:false, barTop:1008, opacity:1, videoH:1008, cursor:auto}
  hidden      {idle:true,  barTop:1080, opacity:0, videoH:1080, cursor:none}  ← 播放中静置 3.4s
  stillHidden {idle:true,  barTop:1080, opacity:0, videoH:1080}               ← 原地补发同坐标 move，不唤醒
  hoverAwake  {idle:false, barTop:1008, opacity:1, videoH:1008}               ← 鼠标停在控制条上
  hoverHidden {idle:true,  barTop:1080, opacity:0, videoH:1080}               ← 停在条上 5.2s 仍会收起
  shown       {idle:false, barTop:1008, opacity:1, videoH:1008}               ← 再动一下鼠标
  pausedIdle  {idle:false, barTop:1008, opacity:1, videoH:1008, paused:true}  ← 暂停后静置不收

几何同线（cy 全部 1055）：
  行 / 进度轨道 / 播放按钮 / 音量按钮 / 音量轨道 / 音量轨道条 / 三个按钮
游标居中：
  进度游标 cy=1055 vs 轨道 cy=1055 → diff 0
  音量游标 cy=1055 vs 轨道 cy=1055 → diff 0

音量：
  点滑杆 40% → video.volume=40, muted=false, memo={v:40}, aria-valuenow=40, fillPct=40
  点喇叭   → muted=true, active=true, aria-valuenow=0, fillPct=0
  再点喇叭 → muted=false, volume=40（回到静音前的值，不是 100）
```

`probe-player-budget` 1440×900 / 1024×700 两档 `contentScroll=0`，纵向预算无回归。

## 5. 红线

- **收条必须同时改画面高度**（含 danmaku 层 `bottom`、mpv 矩形），否则留黑带 / 弹幕被吞。
- **mpv 下不许给视频加高度过渡**，矩形只能一次到位。
- **`.fs-anim` 之前不许启用过渡**，否则进全屏时会看到画面从小盒子长大。
- **任何自定义按钮 / 滑杆写 `height` 都要配 `min-height: 0`**（全局 `button { min-height: 34px }`）。
- **`top: 50%` 配 `transform: scale()` 的圆点必须用独立 `translate` 补 -50%**（本篇第 3 节）。
- **收起必须是心跳自检，不能只靠一次 `setTimeout`**：进全屏那一刻状态没同步好就再也
  排不上计时器，表现为「永不收起」。同理，`hover` 只能延长阈值、不能当硬阻止。
- **`pointermove` 要先做坐标去重**：布局变化后 Chromium 会原地补发一次，否则收起后
  立刻被唤醒，形成周期性闪烁。
