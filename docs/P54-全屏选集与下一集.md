# P54 全屏选集 / 下一集

> 需求：全屏状态下要有「下一集」和「选集」按钮；布局合理、样式与播放器一致、
> 不干扰播放控件；退出全屏恢复原界面。

## 1. 为什么不能用原生全屏

原生 `<video>` 的「全屏」按钮调的是 `video.requestFullscreen()` —— **元素全屏**，
只把 `<video>` 自己推进 top layer。`.video-wrap` 里的兄弟节点（`DanmakuLayer`、
无画面提示、错误卡、我们要加的按钮）一律不渲染。这也是「全屏下弹幕消失」的真正原因，
不是弹幕层的问题。

所以全屏对象改成 **容器 `.video-wrap`**：容器进全屏后里面的一切都跟着进去；
换集只替换 `<video>` 的 `src`，全屏状态不受影响（已实测：面板里点集后
`document.fullscreenElement` 仍是 `.video-wrap`）。

两道入口都需要改：

| 位置 | 处理 |
|---|---|
| 原生控制条的全屏按钮 | 隐藏。`controlsList="nofullscreen"` 在这版 Chromium **实测不生效**（按钮还在），只能用 `video::-webkit-media-controls-fullscreen-button { display:none }` |
| 我们的入口 | 控制条新增「全屏 / 退出全屏」（`.engine-row`），点击走 `toggleFullscreen()` |

> 若原生全屏按钮没被挡住，用户点它就回到「只有画面、没有任何覆盖 UI」的旧行为，
> 等于本批功能白做。这是 §1 里唯一必须二选一的地方。

## 2. 布局：把全屏画面切成两段

```
┌───────────────────────────────┐
│                               │
│   <video>   height: 100% - 72px（object-fit: contain）
│                               │  ← 原生控制条贴在它的底边
├───────────────────────────────┤
│ 片名 · 第 9/42 集 · 集名   [选集][下一集][退出全屏] │  ← .fs-bar，72px
└───────────────────────────────┘
```

- 视频高度扣掉 `--pf-fs-bar`（72px），**原生控制条就自动落在底部条上方**：
  两者在几何上不可能重叠，比「靠 z-index / 定位猜控制条高度」稳。
- 底部条常驻、不跟鼠标自动隐藏 —— 要求是「任何时刻都点得到下一集」，
  跟原生控制条一起淡出就失去了意义。
- 覆盖层 `.fs-ui` 整层 `pointer-events: none`，只有按钮自己 `auto`：
  点画面照旧是播放/暂停，拖进度条、音量、画中画全不受影响。
- 浮层位置统一按「视频区 − 底部条」这块画面区校正：`.seek-hint` 抬到
  `bar + 84px`（原本贴底 64px，全屏下正好落进底部条里），弹幕层
  `bottom: var(--pf-fs-bar)`（否则最下面一两条轨道藏在条后面），
  占位/错误卡按 `(100% - bar) / 2` 居中。

## 3. mpv 内核：子窗口必须一起让位

libmpv 的视频表面是 Win32 **子窗口**，恒画在 DOM 之上（P38 同源结论）。
若照旧把整个视频区交给它，「选集 / 下一集」会被画面永久盖住、点都点不到。
`syncMpvRect()` 里全屏时按同一个常量扣减：

```ts
const h = Math.max(2, r.height - (isFullscreen.value ? FS_BAR_H : 0))
```

`FS_BAR_H = 72` 与 CSS 的 `--pf-fs-bar` **必须一致**，改一处要改两处。
`fullscreenchange` 里还要显式调一次 `scheduleMpvRect()`：全屏同时改了尺寸和位置，
而 ResizeObserver 只看尺寸。

## 4. 交互细节

- **选集面板**：右下角浮层，`max-height: min(52vh, 460px)`，内部滚动；
  打开时把当前集 `scrollIntoView({ block: 'center' })`，几十集的剧点开就在眼前。
  面板底部复用侧栏 `.ep-btn`（`.video-wrap` 带 `force-dark`，token 天然是暗色）。
- **换集失败不关面板**：`onPickFsEpisode` 只在 `sideError` 为空时收起，
  失败原因留在面板里（`浏览器调试模式下 RPC 不可用` 这类）。
- **切换中**：复用 `picking`，底部条显示「正在切换第 N 集…」并禁用两个按钮。
- **焦点**：进全屏后 `video.focus()` —— 容器全屏不会自动转移焦点，
  焦点不在 video 时 P47/P48 的 ← / → 快进就失效。
- **离开播放页**：watch `store.route`，非播放页时 `exitFullscreen()`，
  否则整页只剩一块全屏画面、导航也点不到。
- **Esc**：Chromium 自己会退出全屏（JS 拦不住），`fullscreenchange` 统一收口，
  面板随之关闭。

## 5. 验证（`.probe/p54-fullscreen.mjs`）

真实 Electron 窗口（不用 jsdom：`:fullscreen` 与窗口全屏都只在真环境成立），
入口按钮用 `sendInputEvent` 模拟真实点击（`requestFullscreen` 要求用户手势，
`executeJavaScript` 不算）。喂 42 集假剧集 + ffmpeg 生成的 1280×720 测试视频。

实测（1920×1080 全屏）：

| 断言 | 结果 |
|---|---|
| `document.fullscreenElement` | `video-wrap force-dark` ✓ |
| 视频区 | 1920×1008（= 1080 − 72）✓ |
| 底部条 | y 1008–1080，与视频区零重叠 ✓ |
| letterbox | 画面按 contain 居中，两侧 64px 纯黑（像素采样）✓ |
| 按钮 | 选集 9/42、下一集 第10集、退出全屏，均可用 ✓ |
| 键盘快进提示 | y 894–924，在原生控制条与底部条之上 ✓ |
| 退出全屏 | `fsEl=null`、`.fs-bar`/`.fs-panel` 消失、按钮回到「全屏」、视频区回到 780×439 ✓ |

回归：`.probe/probe-player-budget.mjs` 1440×900 / 1024×700 两档 `contentScroll=0`，
新增按钮没有把控制条挤到换行，纵向预算未变。

## 6. 红线

- **`.video-wrap:fullscreen` 仍不许出现 `border-radius` + `overflow:hidden`**（P38 黑屏）。
  这里显式写 `border-radius: 0; overflow: visible`，全屏元素自带独立合成层。
- **不要给 `.video-wrap` 加 `transform` / `filter`**：会让 `:fullscreen` 的 fixed 定位失效。
- 全屏里的覆盖 UI 一律从 `.video-wrap` 继承 `force-dark` token，不写死色值（P51）。
